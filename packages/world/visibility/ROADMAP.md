## Completion Denominator

This leaf roadmap contains exactly 18 behavior rows. [`inventories/visibility-systems.md`](inventories/visibility-systems.md) contains 42 Candidate system items and 0 Accepted items because no checked-in generator or denominator review exists. The current completion denominator is therefore 18 behavior rows. Acceptance of all 42 inventory items would make the denominator 60 items.

The denominator covers runtime-neutral visibility for Source 1 BSP worlds used by Team Fortress 2, Counter-Strike: Source, and legacy Source 1 Counter-Strike: Global Offensive: semantic BSP traversal, PVS and PAS expansion and queries, area connectivity, camera-effective area portals, portal view windows, map occluders, sky classification, leaf membership for world surfaces and presentation candidates, ordered world-list results, bounded caches, and dynamic invalidation.

The denominator is Not accepted. Reviewer identity, review date, reviewed commit, a generated inventory, and a passing denominator-review record are Missing.

## Outputs

- Exact point-to-leaf and point-to-cluster results; bounded AABB-to-leaf results; PVS and PAS cluster bitsets; cluster, leaf, head-node, point, and box visibility decisions; and area-connectivity results.

## Invariants

- Construction validates the complete semantic graph before publishing a visibility world. A published world is immutable; dynamic state is separate and revisioned.
- Initial dynamic state is revision 0, contains no dynamic objects, marks every compiled portal key closed, and derives each occluder's active state from its compiled inactive flag. Updates start at revision 1, are contiguous, and apply one whole revision atomically; gaps, repeats, unknown removals, and out-of-range identities are Malformed.
- Node child references use non-negative node indexes and negative leaf encoding `-(leaf + 1)`. Every reference is in range, every node plane is finite and in range, every model head node is valid, and the node graph is acyclic. A path visits at most the validated node count.
- Point traversal starts at the declared world head node. A plane distance less than zero selects child 1; zero and positive distances select child 0. Point queries reject NaN, infinity, and coordinates outside `[-32768, 32768]` on any axis.
- Standalone AABB leaf enumeration visits child 0 before child 1 whenever the box crosses a plane. A view world-list traversal instead visits the camera-side child first and child 0 first on an exact camera-plane tie.
- Leaf cluster `-1` means no cluster. Every other leaf cluster is non-negative, representable by the signed 16-bit leaf field, and less than the declared cluster count. When visibility bytes are present, their cluster count equals the semantic cluster universe derived from leaves.
- One PVS or PAS row expands to exactly `ceil(clusterCount / 8)` bytes. A nonzero byte is literal; a zero byte is followed by one nonzero run length. Truncation, a zero-length run, an overrun, an offset inside the header, a negative or out-of-range offset, and nonzero padding bits beyond the final cluster are Malformed.
- Direct visibility for cluster `-1` is an empty bitset. A view whose finite origin resolves to cluster `-1` is outside-world and returns every PVS-, area-, portal-, and occluder-gated candidate without claiming that any candidate is drawn.
- An empty BSP visibility lump is the valid no-vis map mode and expands every declared PVS and PAS cluster bit. An explicit PVS-bypass query has the same cluster result. Neither mode disables caller-owned frustum, distance, LOD, material, or draw policy.
- Multi-origin visibility is the bitwise union of the individually expanded PVS rows after origins are converted to clusters. Duplicate clusters do not change output. Origins are sorted by cluster identity for cache identity while the caller's origin order remains observable in diagnostics.
- Area 0 is retained as the non-area sentinel. Portal state is keyed by compiled portal key; all directed records sharing a key change atomically. Connectivity is reflexive and is the transitive closure of currently open directed portal pairs.
- Every directed portal has at least one reciprocal record with the same portal key and reversed source and destination areas. Repeated reciprocal records are retained. A missing reciprocal relation is Malformed; accepted connectivity is therefore symmetric.
- Camera-effective portal state keeps topology-open state separate from per-view flow eligibility. Explicitly closed portals never flow. Distance windows, FOV adjustment, portal-plane side, clip geometry, and nested portal-window intersections affect only the current view result.
- Generic portal flow is eligible when topology is open and `planeDistance + 80 > 0`; its presentation-open result ignores that backside test. A distance-window portal additionally requires `adjustedBoundsDistance <= fadeEndDistance + 10` for both results. Camera area flow requires directed `planeDistance >= -0.1` and the presentation-open result.
- Portal windows use at most 32 ordered clip vertices per directed portal, clip against the declared view, and intersect with the parent normalized window. A portal reached by multiple paths contributes the smallest normalized rectangle containing every reached window. Empty intersections do not expose the destination area.
- Perspective field-of-view values are greater than 0 and less than 180 degrees. Orthographic left is less than right and bottom is less than top. Near distance is positive, far distance is greater than near, portal tolerance is non-negative, and FOV distance-adjust factor is positive. Every projection and camera scalar is finite.
- Occluder activation changes no BSP geometry. Occlusion tests consume only active, front-facing polygons in visible areas, clip them to the declared near plane and view, apply the declared minimum occluder and maximum occludee screen-area thresholds, and return `occluded` only when the complete projected AABB is covered.
- Sky classification is exactly `3D sky`, `2D sky`, or `not visible`. `3D sky` takes precedence when a selected camera leaf carries both sky flags. Multi-origin results choose `3D sky` over `2D sky` over `not visible`.
- Static props use their compiled leaf lists. Dynamic objects use current AABBs and are relinked after every accepted bounds update. Detail-prop placement and fade remain outside this package; visibility returns detail-prop candidates only through their compiled leaf membership.
- Visible leaves are emitted front-to-back by camera-side BSP traversal, selecting child 0 first on an exact plane tie. World surfaces and candidates are deduplicated at first encounter; compiled memberships preserve source order and dynamic candidates use stable identity order.
- A decompressed-row cache key contains map identity, visibility kind, and cluster. A merged-cluster cache key contains map identity and the sorted unique cluster tuple. A complete view cache additionally contains exact view bits, query flags, limits, and state revision. Portal, occluder, dynamic-membership, map, or limit changes cannot reuse an older complete-view result.
- Cache eviction changes performance only. Cached and uncached queries return byte-identical ordered outputs and identical errors.
- Every count, multiplication, addition, allocation, membership insertion, recursive-equivalent traversal, and output append is checked against integer range and the supplied limit before allocation or mutation. Limit failure returns no partial authoritative result.

## Ownership Exclusions

- BSP byte ranges, record decoding, lump versions, and lossless format representation belong to `packages/formats/bsp`. Visibility consumes typed records and owns their runtime-neutral semantic validation and queries.
- Canonical map assembly, face topology, brush-model assembly, static-prop placement, detail-prop placement, and runtime descriptors belong to `packages/world/map`.
- Collision contents, ray traces, hull sweeps, overlaps, contacts, and collision acceleration belong to `packages/world/collision`. Visibility traversal cannot answer collision questions.
- Area-portal entity keyvalues, inputs, outputs, parenting, lifecycle, and game-specific entity state belong to `packages/world/entity` and the selected game. Visibility consumes explicit portal state and owns area connectivity and view-flow results.
- Gameplay relevance, replicated-field selection, recipient selection, snapshot policy, and transport belong to simulation, the selected game, and `packages/runtime/networking`. Visibility supplies PVS and PAS queries only.
- General view-frustum culling, model LOD selection, prop and detail fade, translucency sorting, material selection, draw grouping, GPU resources, GPU occlusion queries, and pixels belong to `packages/presentation/rendering`. Visibility supplies ordered candidates, portal windows, occlusion decisions, and unchanged LOD inputs.
- Detail-prop model or sprite creation, animation, sway, lighting, and drawing belong to map and presentation owners. Visibility owns only leaf membership and candidate enumeration.
- Sound event creation, attenuation, spatialization, mixing, and playback belong to the selected game and `packages/presentation/audio`. PAS expansion does not choose listeners or sounds.
- Product toggles, diagnostics UI, camera ownership, and browser lifecycle belong to applications and tools.
