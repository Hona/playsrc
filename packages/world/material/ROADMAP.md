# Material Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery statuses, coverage classifications, inventory, logical path, and Complete.

## Completion Denominator

The current completion denominator contains exactly the 35 Behavior Families rows below. The candidate inventories enumerate 130 PC shader registrations, 484 parameter identities, 50 material-state flags, and 84 TF2-client proxy registrations. These 748 candidates contribute 0 denominator items until checked-in generators reproduce them from exact authorities and a denominator review accepts this roadmap.

The current denominator is Not accepted. Its target is runtime-neutral Source 1 material resolution for the exact declared PC content builds of Team Fortress 2, Counter-Strike: Source, and legacy Source 1 Counter-Strike: Global Offensive. Source 2 material resources and GPU execution are excluded.

## Inputs

- One immutable `VmtEffectiveDocument`, its canonical `materials/<name>.vmt` logical identity, complete VMT composition trace, and provenance from `packages/formats/vmt`.
- One explicit material-selection environment containing game, content build, PC shader profile, HDR mode (`None`, `Integer`, or `Float`), shader-model support level, pixel-shader-2_b support, sRGB-correct-blending state, low-fill state, editor-material permission, and model-use context. Material resolution never derives this environment from the browser or GPU.
- One shader registry containing ASCII-insensitive shader and alias identities, ordered parameters, declared types, declared defaults, effective initialization rules, declared shader-selection edges, derived flags, and semantic-family contracts.
- One proxy registry containing ASCII-insensitive proxy identities, ordered argument contracts, required material variables, evaluation-input dependencies, output mutations, and game-owned evaluator dependencies.
- A texture dependency callback receiving the parent material identity, exact decoded reference token, semantic role, canonical `materials/<name>.vtf` request identity, and remaining budgets. It returns VTF metadata, decoded-plane availability, and provenance or `Missing`.
- A material dependency callback with the equivalent contract for selected material references and canonical `materials/<name>.vmt` identities. It returns resolved VMT input plus provenance or `Missing`.
- One evaluation context containing absolute presentation time, frame interval, deterministic random samples, entity binding identity, immutable generic entity presentation values, and an optional game-owned proxy-input snapshot. Omitted required fields are `Missing`; wall-clock time and ambient process state are never read.
- A required limits record containing `maxParameters`, `maxDependencies`, `maxDependencyDepth`, `maxSelectionSteps`, `maxProxies`, `maxProxyArguments`, `maxEvaluationSteps`, `maxReferenceBytes`, `maxOwnedBytes`, and `maxDiagnostics`. The package defines no unbounded mode.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/materialsystem/{IShader.h,imaterial.h,imaterialvar.h,imaterialproxy.h,imaterialproxyfactory.h,imaterialsystem.h}`, `src/public/shaderlib/{BaseShader.h,cshader.h}`, `src/materialsystem/stdshaders/{stdshader_dx9_inc.vpc,*.cpp}`, and TF2 client build and proxy sources under `src/game/client/{client_base.vpc,client_econ_base.vpc,client_tf.vpc,tf/**}` and `src/game/shared/{econ,tf}/**`.
- Exact archive indexes, VMT bytes, VTF metadata, shader-registry captures, and proxy-registry captures for one declared content build of each target game. These inputs are Missing.

## Outputs

- An immutable `ResolvedMaterial` containing canonical identity and provenance; selected shader and selection trace; ordered typed variables with source/default/proxy origin; author flags, defined masks, derived state flags, and per-entry coverage classifications.
- Ordered `TextureDependency` and `MaterialDependency` records containing exact source token, semantic role, canonical request identity, returned provenance, and dependency edge.
- Runtime-neutral static state containing lighting model, blend equation and factors, alpha test, culling, depth test/write/function, polygon-offset role, fog participation, vertex-input requirements, color and alpha modulation, and framebuffer-input requirements.
- Typed feature state for base textures, transforms, frames, detail layers, bump and normal maps, self illumination, environment mapping, phong, water, sky, and decals.
- An immutable `MaterialEvaluationProgram` containing ordered proxy operations and their declared input dependencies. Evaluating it is pure over `ResolvedMaterial` plus one evaluation context and returns `EvaluatedMaterialState` plus a step trace; it never mutates shared material state.
- Stable diagnostics containing coverage classification, code, material identity, VMT source span, shader or proxy identity, parameter or argument identity, dependency chain, evaluation step, and no substitute material.

## Invariants

- Resolution and evaluation are deterministic over supplied documents, registries, dependency results, environments, contexts, and limits. They perform no filesystem access, provider selection, archive scan, network request, installation discovery, GPU query, wall-clock read, or game-state mutation.
- Shader, parameter, flag, and proxy lookup ignores ASCII case while retaining source spelling and registry identity. No unknown identity selects a similarly named shader, parameter, proxy, or material.
- Shader-declared selection, material-condition selection, and `$fallbackmaterial` are successful data-selection operations only when every selected edge resolves. Unknown, cyclic, missing, malformed, or over-limit selection returns its exact classification and never substitutes an error material or second implementation.
- Explicit active values are parsed before shader initialization. Shader-declared initialization then supplies only values that remain undefined. Every output variable records whether it came from VMT syntax, a selected override block, a declared initializer, a derived flag, or a proxy step.
- Unknown variables remain ordered typed variables because a later proxy can reference them. They cannot affect static material state until an accepted parameter or proxy contract assigns semantics.
- Texture and material references retain their exact source tokens. Material constructs one canonical dependency request per active external reference; Content alone validates provider eligibility and selects bytes.
- Render targets, environment lookups, and other accepted non-file bindings are typed reference kinds. They never generate guessed file requests.
- Texture frames are zero-based. VTF supplies frame count and decoded planes; Material owns static frame parameters and proxy-driven frame selection. A frame outside the supplied count is `Malformed` unless the accepted proxy contract explicitly wraps or clamps it.
- Texture transforms are finite 4×4 matrices with an exact source lexeme and operation trace. Center, scale, rotation, and translation order is fixed by the transform contract; malformed or non-finite transforms never become identity transforms.
- Proxies initialize and evaluate in VMT source order. Step `n` reads the variable state produced by step `n-1`; repeated proxy identities remain repeated operations. Every declaration records an initialized operation or an explicit classified no-operation disposition, and later declarations retain their source positions.
- Time-dependent proxies use supplied absolute presentation time and frame interval. Entity-dependent proxies use the supplied entity snapshot. Game-dependent proxies consume only a game-owned typed input. Random proxies consume supplied samples. Missing context never becomes zero, local player state, or process randomness.
- `ResolvedMaterial` and `EvaluatedMaterialState` describe semantics and required presentation work. They contain no browser object, GPU handle, shader module, draw command, scene mutation, or resource-lifetime policy.
- Every count, depth, string byte length, dependency, selection step, evaluation step, allocation, callback, and diagnostic is checked against the limits record before use.
- Source 2 shaders, KV3, compiled material resources, compatibility layers, legacy output schemas, and fallback implementations never enter this package.

## Ownership Exclusions

- `packages/formats/vmt` owns VMT/KeyValues structure, source spans, patch dependency requests, and patch composition. Material consumes one effective document and never reparses text or re-applies patches.
- `packages/formats/vtf` owns VTF metadata, frames, faces, slices, formats, resources, and decoded planes. Material owns reference role, color/normal interpretation, and frame-selection semantics.
- `packages/content` owns logical-path validation, provider order, exact byte retrieval, active-map PAK precedence, caching, and provenance acquisition. Material owns only reference-token classification and dependency requests.
- `packages/presentation/rendering` owns GPU shaders, resource lifetime, texture upload and sampling, draw sorting, pass scheduling, reflection and refraction targets, draw policy, and pixels. Material owns the runtime-neutral state those operations consume.
- `packages/world/map` owns map-wide sky-face assembly, water-surface and volume association, decal geometry association, lightmap association, and immutable map roots.
- `games/tf2`, `games/css`, and `games/csgo` own game-state derivation, game-specific effect selection, and typed values supplied to game-dependent proxy operations. Material owns proxy ordering and application of supplied values to material variables.
- `packages/presentation/particle` owns particle sequence use and particle frame selection. `packages/world/material` owns only material-level texture animation declared by a material proxy.
- Applications own product configuration and presentation-time sources. Tools own orchestration and inventory generation.

## Exit Criteria

Material is Complete only when all of these predicates pass:

- All 35 Behavior Families rows are Ready.
- The shader, parameter/flag, and proxy inventories are generated, current, Accepted, and cover exact TF2, CS:S, and legacy Source 1 CS:GO content builds with no unclassified VMT occurrence.
- Every registered shader and alias has one selected semantic contract; every effective parameter has one type, declared default, effective initialization result, origin, and coverage classification.
- Every author/runtime flag and derived-state flag has exact isolated and combination evidence.
- Every encountered proxy has exact initialization, input-dependency, ordering, mutation, and failure evidence. Every game-dependent proxy is integrated through its game-owned typed input.
- Fixed vectors cover conditions, shader and material selection, dependencies, cycles, transforms, frames, proxies, alpha, depth, culling, blending, lighting, self illumination, environment mapping, detail, bump, phong, water, sky, decals, and every limit.
- VMT, VTF, Content, Map, TF2, CS:S, legacy CS:GO, Rendering, Particle, and tools consume the sole current Material interface; no embedded material resolver, direct VMT interpretation, placeholder material, compatibility layer, or legacy artifact reader remains.
- No required declared-content material, shader, parameter, flag, proxy, reference, or state remains `Unsupported`, `Unknown`, `Missing`, `Malformed`, `Partial`, or `Blocked`.

## Blockers

- **Exact target content:** `playsrc.local.json` is Missing. No configured TF2 archive index or VMT/VTF byte set is available, and the local configuration contract has no CS:S or legacy CS:GO root. Exact per-build occurrence counts and content hashes cannot be generated. Checked `playsrc.local.example.json`, the current Content/VMT/VTF roadmaps, and the assigned Material tree.
- **Target registries:** the official SDK source produces finite candidate shader, parameter, flag, and TF2 proxy sets, but no checked-in operation captures and hashes the exact registries for the declared retail content builds. Effective parameter defaults and build-conditioned registrations cannot be accepted from source candidates alone. Checked the SDK build inputs, public registry interfaces, assigned inventories, and `tools/`.
- **Inventory generator:** no checked-in `tools/playsrc` command emits any assigned Material inventory. Production implementation is outside this roadmap-research checkpoint. Checked `tools/`, root manifests, and the complete assigned Material tree.
- **Semantic prerequisites:** VMT, VTF, and Content denominators are Not accepted and their implementations do not exist. Material cannot complete dependency, texture-metadata, or integration evidence until those current interfaces are available. Checked all three public roadmaps and their current inventories.
- **Game-dependent proxy integration:** the TF2 game roadmap is absent, and CS:S and legacy CS:GO remain Future targets. Their typed proxy-input inventories and integration evidence are unavailable; Material can define the seam but cannot establish game-derived values. Checked the root Owner Registry, all three game READMEs, and current game roadmap paths.
