# Map Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery status, coverage classification, Map package, canonical representation, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 21 behavior rows. [`inventories/map-sections.md`](inventories/map-sections.md) defines 27 candidate canonical map sections. Those sections contribute 0 denominator items until a checked-in generator emits the inventory and a denominator review accepts it. The current completion denominator therefore contains 21 items. Acceptance of all 27 candidate sections would make the denominator 48 items.

The target is one immutable, runtime-neutral map representation for each declared Team Fortress 2, Counter-Strike: Source, or legacy Source 1 Counter-Strike: Global Offensive map input. Every representation preserves Source coordinates, carries world geometry references, joins parsed BSP identities to current material, StudioModel, entity, collision, and visibility outputs, and passes complete referential integrity validation. Source 2, console-specific map containers, editable VMF reconstruction, rendering resources, game behavior, publication, and storage are excluded.

The denominator is Not accepted. The section inventory has no generator or review record, required producer roadmaps and interfaces are incomplete, exact declared-content map indexes are Missing, and direct native/WASM compilation evidence does not exist.

## Inputs

- One `MapCompileRequest` whose identity is exactly `{game, contentBuild, map}`. `game` is `tf2`, `css`, or `csgo`; `map` is the exact `maps/<name>.bsp` logical path; `contentBuild` is the configured provider's content-build identity or `Unknown` only when that provider exposes no build identity.
- One successfully parsed BSP document from `packages/formats/bsp` with selected profile, container version, signed map revision, complete typed and opaque lump results, source provenance, and SHA-256 of the exact BSP bytes. The request game, map logical path, content build, profile, and BSP provenance must agree.
- Finalization receives current semantic outputs requested by exact role and identity from `packages/world/material`, `packages/formats/studio-model`, `packages/world/entity`, `packages/world/collision`, and `packages/world/visibility`. Every output supplies its owner, current interface identity, source-map identity and hash when map-derived, assembly-plan identity for collision and visibility, stable item identities, coverage classifications, artifact descriptors, and transitive input hashes.
- A dependency callback that receives `{sectionId, itemId, role, logicalPath}` and returns exactly one current semantic output with provenance and content hash or `Missing`. The Map package never searches providers, probes alternate paths or extensions, parses dependency bytes, or substitutes another dependency.
- One build configuration containing exactly `lightingProfile` and `limits`. `lightingProfile` is `ldr` or `hdr`; there is no automatic profile selection. `limits` contains non-negative unsigned values for `maxItems`, `maxDirectReferences`, `maxTransitiveReferences`, `maxDependencyDepth`, `maxDependencyBytes`, `maxManifestBytes`, and `maxDiagnostics`. No field has a default and no unbounded mode exists.
- One compiler-behavior identity containing the current Map interface identity, repository commit, and lowercase SHA-256 of the checked-in machine-readable behavior manifest used by the compiler.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/bspfile.h`, `gamebspfile.h`, `worldsize.h`, `vphysics_interface.h`; `src/utils/vbsp/writebsp.cpp`; `src/game/shared/mapentities_shared.*`; and the public map consumers in `src/game/server/world.cpp`, `SkyCamera.cpp`, `fogcontroller.cpp`, `WaterLODControl.cpp`, `rope.cpp`, `lights.cpp`, `env_tonemap_controller.cpp`, and `shadowcontrol.cpp`.

## Outputs

- Preparation emits one immutable, non-runtime `MapAssemblyPlan` containing the exact request/BSP identities, build and compiler-behavior hashes, map-owned source occurrence tables, unresolved dependency requests, and typed collision/visibility assembly views. Its identity is exactly `{game,contentBuild,map,bspSha256,buildConfigurationSha256,compilerBehaviorSha256}`. It is the only input from which child map-derived semantic outputs may be built and cannot be published or consumed as a partial map.
- Successful finalization of one plan and all required child outputs emits an immutable `CanonicalMap` containing the exact request identity, plan identity, BSP source identity, Source spatial frame, selected lighting profile, build-configuration hash, compiler-behavior identity, and exactly the 27 section descriptors in inventory order.
- Each section descriptor contains exactly `id`, `classification`, `itemCount`, `artifact`, and `dependencies`. `id` is an accepted inventory identity; `classification` is `Handled` or `Intentionally inert`; `itemCount` is a canonical unsigned decimal string; `artifact` is one immutable `{kind:"artifact",mediaType,byteLength,sha256}` descriptor whose media type is an accepted producer value, byte length is a canonical unsigned decimal string, and SHA-256 is lowercase 64-hex; and `dependencies` is a duplicate-free artifact-descriptor array sorted by kind then SHA-256.
- A frozen `MapRuntimeDescriptor` containing map source identity, every consumed raw object, compiler/configuration identities, canonical section objects, runtime representations, coverage classifications, and diagnostics. Its duplicate-free references are sorted by kind then SHA-256. It is emitted automatically after successful compilation and can run in memory without publication. `packages/asset-store` owns optional persistent storage and publication of the descriptor and referenced objects.
- A deterministic dependency trace ordered by section identity, item identity, dependency role, and logical path. Every entry records the request, result, owner, provenance, content hash, artifact descriptor, and coverage classification.
- A deterministic assembly report containing all direct and transitive input hashes, build-configuration hash, compiler-behavior identity, section and item counts, selected lighting profile, dependency trace identity, root-description identity, and diagnostics sorted by validation stage, section inventory order, item identity, dependency role, logical path, and error code.
- Preparation failure emits no `MapAssemblyPlan`. Finalization failure emits no `CanonicalMap` or `MapRuntimeDescriptor`; the immutable plan remains non-authoritative. Diagnostics use exactly `MalformedRequest`, `ProducerRejected`, `IdentityMismatch`, `DuplicateIdentity`, `MissingSection`, `MissingDependency`, `UnsupportedSection`, `UnknownSection`, `MalformedReference`, `HashMismatch`, `IncompleteLightingProfile`, or `BoundExceeded` and record classification, validation stage, section, item, role, logical path, offending identity or value, and bound when applicable.

## Invariants

- Canonical coordinates remain Source XYZ: X is forward/east, Y is left/north, and Z is up. One Source unit is one inch. Positions are inches, angles are degrees, QAngle order is pitch about Y, yaw about Z, and roll about X. No GLB, renderer, physics-adapter, or application coordinate transform enters canonical map data.
- The nominal Source coordinate interval is `[-16384, 16384]` on each axis. Every canonical coordinate is finite. An encountered finite coordinate outside that interval is `Unsupported` until an accepted declared-content contract establishes its required handling; values are never clamped.
- Bounds retain three distinct identities: the nominal coordinate interval; each BSP brush model's ordered minimum and maximum; and world gameplay bounds from worldspawn `world_mins` and `world_maxs`, which exclude 2D and 3D sky geometry. Missing, non-finite, reversed, or out-of-range required bounds prevent output.
- BSP source indexes remain canonical cross-section identities. Face, displacement, brush-model, leaf, cluster, material-reference, world-light, static-prop, detail-prop, overlay, cubemap, and entity indexes are never renumbered, merged, or inferred from position or name.
- Brush model `0` is the world model. Entity model value `*N` refers only to brush-model index `N`; duplicate entity references remain distinct entity items. A missing world model, overlapping model face ranges, or out-of-range `*N` is Malformed.
- Every displacement has exactly one source displacement index and one parent face identity. Map coordinates displacement ownership and references; collision queries, visibility, lighting evaluation, tessellation policy, and rendering remain with their named owners.
- `ldr` selects standard face, lighting, world-light, leaf-ambient, detail-lighting, cubemap, sky-resource, and static-prop-lighting references. `hdr` selects the corresponding HDR references and is accepted only when the complete profile required by the selected BSP profile exists. Missing HDR members are `IncompleteLightingProfile`; the compiler never selects LDR instead.
- For map logical path `maps/<name>.bsp`, cubemap index `i` at integer origin `(x,y,z)` requests `materials/maps/<name>/c<x>_<y>_<z>.vtf` under `ldr` and `materials/maps/<name>/c<x>_<y>_<z>.hdr.vtf` under `hdr`; `i` remains the item identity when origins duplicate. A required 2D sky named `<sky>` requests exactly `materials/skybox/<sky><suffix>.vmt` under `ldr` and `materials/skybox/<sky>_hdr<suffix>.vmt` under `hdr`, in suffix order `rt`, `lf`, `bk`, `ft`, `up`, `dn`. Material owns all child texture selection and missing profile-selected material or texture bytes fail without trying the other path.
- All four face light-style bytes and every world-light style value are retained. `255` terminates a face's contiguous style list; styles after the first `255`, style values outside 0 through 63, and sample ranges inconsistent with style count are Malformed. Style animation and light contribution belong to entity and rendering owners.
- A valid empty section is emitted as `Intentionally inert` with zero items and an immutable empty-section artifact. A required singleton or a section required by an encountered reference cannot be converted to empty.
- Every section item has exactly one inventory owner. Map may coordinate a child artifact, source index, placement, or relationship but cannot reinterpret child material, model, entity, collision, visibility, physics, game, or rendering semantics.
- Every direct and transitive dependency is resolved from its exact logical identity once. Two responses for one identity must have identical owner, bytes, hash, and descriptor; disagreement is `HashMismatch` or `IdentityMismatch`, never provider precedence.
- Preparation validates BSP-local structure and freezes child input views before any collision or visibility build. Tools invoke child packages with those views, then call finalization with outputs that name the exact plan and BSP hashes. Map, Collision, and Visibility do not import one another's implementations or mutate the plan.
- All arrays retain declared source order unless the output contract explicitly requires sorted identity order. Sets, artifact references, dependency traces, and diagnostics use their declared stable sort keys. Host map iteration, filesystem order, locale, thread completion, and absolute paths cannot affect output.
- Compilation is pure over the request, supplied parsed/semantic values, dependency responses, configuration, and compiler-behavior identity. The package retains no mutable process-global, prior-map, cache, filesystem, renderer, or cross-request state.
- Limits are charged before request dispatch, allocation, hashing, reference insertion, diagnostic insertion, or serialization. Exceeding any caller limit emits `BoundExceeded` and no authoritative partial output.
- Validation cannot mutate parsed or semantic inputs. Successful output is deeply immutable. Failure diagnostics and dependency traces are non-authoritative and cannot be consumed as a partial map.

## Ownership Exclusions

- BSP, game-lump, PAK, and external-lump parsing, byte ranges, compression, versions, and lossless representation belong to `packages/formats/bsp`.
- Exact logical-path normalization, provider order, archive lookup, byte retrieval, caching, and provenance acquisition belong to `packages/content`.
- VMT/VTF parsing and material shader, parameter, proxy, texture, animation, and surface-property semantics belong to `packages/formats/vmt`, `packages/formats/vtf`, and `packages/world/material`.
- MDL, VVD, VTX, ANI, VHV, and PHY parsing and model geometry, skeleton, animation, and collision references belong to their format owners. Map owns only map occurrence and cross-section association.
- Entity tokenization, ordered key/value meaning, class behavior, I/O, lifecycle, fog transitions, rope simulation, controller state, and game-specific entities belong to `packages/world/entity`, runtime packages, and `games/<game>`.
- Collision shape construction, contents meaning, traces, sweeps, overlaps, contacts, and surface query results belong to `packages/world/collision`; rigid-body and constraint behavior belongs to `packages/runtime/physics`.
- PVS/PAS expansion, area-portal state, occlusion decisions, leaf queries, and culling policy belong to `packages/world/visibility`.
- Geometry buffers, lightmap atlases, world-light evaluation, light-style composition, overlay/decal projection, cubemap sampling, sky passes, fog pixels, water rendering, prop lighting, and GPU resources belong to `packages/presentation/rendering`.
- TF2-, CS:S-, and legacy Source 1 CS:GO-specific entities, static-prop flags, objectives, movement, gameplay, and presentation mappings belong to their game modules.
- Derived-cache envelope bytes, object descriptors, graph validation, SHA-256 object identity, retention, storage, synchronization, channels, and publication belong to `packages/asset-store`; command orchestration belongs to `tools/*`. Neither owner can make publication a prerequisite for direct browser compilation.
