# Entity Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery statuses, coverage classifications, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 32 Behavior Families rows. [`inventories/generic-behaviors.md`](inventories/generic-behaviors.md) contains 72 candidate generic behavior items and contributes 0 denominator items until a checked-in generator emits it and a denominator review accepts this roadmap. The current completion denominator is therefore the 32 behavior rows. Acceptance of all 72 inventory items would make the denominator 104 items.

The denominator is Not accepted. It covers runtime-neutral Source entity-lump syntax, identity, keyvalues, handles, references, lifecycle, hierarchy, I/O, templates, generic filter composition, collision-supplied trigger contacts, generic logic primitives, snapshots, deterministic ordering, and bounds. It contains no game classname inventory.

## Inputs

- Immutable BSP entity-lump bytes with map provenance and source byte range. The sequence may end in exactly one NUL byte; a NUL at any earlier position is Malformed.
- A selected-game class-binding registry. Each encountered classname maps to exactly one generic behavior composition, one game-owned handler, `Intentionally inert`, `Unsupported`, or `Unknown`; the Entity package never infers behavior from spelling.
- A fixed simulation tick, positive tick interval, monotonic current tick, and deterministic random stream with serializable state for random timer intervals and case selection.
- Ordered direct-input, lifecycle, and collision-contact batches. Every item carries a producer sequence, target handle or target expression, typed parameter, activator handle, caller handle, and output-action identity when applicable.
- A caller-supplied attachment-transform provider keyed by parent handle and attachment identity. Missing attachments return `Missing`; Entity does not derive animated poses.
- A required limits record containing `maxEntityLumpBytes`, `maxEntities`, `maxKeyValues`, `maxKeyValuesPerEntity`, `maxHierarchyDepth`, `maxOutputActions`, `maxQueuedEvents`, `maxEventsPerTick`, `maxTemplateInstances`, `maxTriggerContacts`, `maxSnapshotBytes`, and `maxDiagnostics`. The package defines no unbounded mode. `maxEntities` cannot exceed 8,192; one entity token cannot exceed 2,047 bytes; one output-action field cannot exceed 255 bytes.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/{basehandle.h,const.h,datamap.h}`, `src/game/shared/{baseentity_shared.cpp,ehandle.h,entitylist_base.h,entitylist_base.cpp,mapentities_shared.h,mapentities_shared.cpp}`, and `src/game/server/{baseentity.h,baseentity.cpp,cbase.cpp,entitylist.h,entitylist.cpp,mapentities.h,mapentities.cpp,variant_t.h,entityinput.h,entityoutput.h,eventqueue.h,hierarchy.h,hierarchy.cpp,TemplateEntities.h,TemplateEntities.cpp,point_template.h,point_template.cpp,filters.h,filters.cpp,triggers.h,triggers.cpp,logicrelay.h,logicrelay.cpp,logicentities.cpp,gameinterface.cpp,saverestore_gamedll.cpp}`.

## Outputs

- An immutable `EntitySyntaxDocument` retaining the complete source byte sequence, ordered entity blocks, ordered repeated key/value token bytes, quoted or unquoted form, semantic key identity, and half-open byte spans.
- An immutable ordered entity-definition set containing source ordinal, classname, targetname, typed field projections, output actions, parent and attachment requests, template membership, class binding, provenance, and one coverage classification per record and field.
- One `EntityWorld` containing live slot/generation handles, creation order, lifecycle state, references, parent/child links, local and world transforms, output-action state, queued events, template state, filter graph, trigger-contact sets, generic logic state, and deterministic random-stream state.
- An ordered `EntityTransitionBatch` containing accepted inputs, rejected inputs, emitted outputs, scheduled or cancelled events, lifecycle changes, reference changes, generic effect requests, diagnostics, and the next entity state.
- An `EntitySnapshot` sufficient to restore every Entity-owned state bit and ordering key against the same source identity and class-binding registry identity.
- Diagnostics containing coverage classification, stable code, map identity, entity source ordinal, handle when allocated, key/value or action span, tick, producer sequence, target expression, input identity, violated bound or invariant, and causal dependency result.

## Invariants

- Entity-lump strings are Source byte tokens, not inferred UTF-8. ASCII-insensitive operations fold only `A` through `Z`; stored bytes and spelling never change.
- Entity blocks, key/value pairs, repeated keys, output declarations, and entities preserve source order. A map or object keyed by field name is never the canonical representation.
- Semantic lookup returns the first ASCII-insensitive key match. Raw duplicate suffixes, trailing key bytes, and every later duplicate remain observable even when a class binding derives a normalized semantic key.
- A live handle is a slot plus generation. Removing an entity invalidates every prior handle before that slot can identify another entity. Targetnames and classnames are not handles.
- Exact targetname resolution precedes classname fallback. Valid wildcard syntax is either an exact expression or one trailing `*`; results follow live creation order. Context selectors resolve at dispatch time from the event's searching entity, activator, and caller.
- Parent links form an acyclic forest. Reparenting and detaching preserve the child's world transform unless an attachment-snap input explicitly selects zero local offset. Descendant world transforms are derived once from parent world transform and child local transform.
- Input names are ASCII-insensitive. Every dispatch retains target, input, typed parameter, activator, caller, output-action identity, tick, and sequence through success or failure.
- Output actions fire in the target's observable reverse declaration order. Equal-due-time queue entries preserve enqueue order. Finite fire counts are consumed when an action emits an event, whether or not dispatch later finds a target or accepted input.
- Servicing one tick consumes every due event, including a newly enqueued event already due in that tick, until the queue is quiescent or `maxEventsPerTick` is reached. Reaching the bound returns `BoundExceeded` with the unprocessed queue intact.
- Removing an entity cannot cancel a name-targeted event merely because it supplied that name when the event was queued. A direct-handle target becomes stale; target expressions resolve against the live world at dispatch.
- A classname without an accepted class binding never receives guessed generic behavior. Its record and keyvalues remain available with exactly one coverage classification.
- Collision produces contacts and owns overlap geometry. Entity owns filter evaluation, the accepted contact set, first/last-contact transitions, trigger I/O, and contact-state snapshots.
- Every count, source span, allocation, traversal, recursion step, queued event, emitted transition, contact, template instance, diagnostic, and snapshot byte is checked against the required limits before mutation or allocation.

## Ownership Exclusions

- `packages/formats/bsp` owns the entity-lump byte range and BSP container integrity. This package owns tokenization and semantic entity records after receiving those exact bytes.
- `packages/world/map` owns map-wide assembly and immutable references to geometry, brush models, collision, visibility, and environment data. Entity owns no duplicate map representation.
- `games/<game>` owns every game classname assignment, game-specific key and input meaning, player/team/class predicates, damage, teleport, spawn, objective, item, weapon, and rules behavior. A game maps each classname to generic Entity primitives or to one game-owned handler.
- `packages/runtime/movement` owns mover trajectories, velocity, blocking, stepping, and carried-subject motion. Entity may dispatch and record movement requests and completion inputs but cannot compute movement.
- `packages/runtime/physics` owns rigid bodies, constraints, forces, mass, and physics integration. `packages/world/collision` owns shapes, traces, sweeps, overlaps, and contact production.
- `packages/runtime/simulation` owns the gameplay tick and phase schedule. Entity owns deterministic ordering only inside the Entity phase invoked by Simulation.
- `packages/runtime/networking` owns wire entity indexes, replicated-handle encoding, snapshots on transports, and prediction transport. Generic slot/generation identity remains Entity-owned.
- `packages/runtime/replay` owns recorded-state advancement. It may consume Entity snapshots but cannot advance Entity gameplay state.
- `packages/presentation/rendering`, `packages/presentation/particle`, and `packages/presentation/audio` consume Entity state and effects without becoming lifecycle, hierarchy, or I/O authorities.
- Studio-model and game animation owners produce attachment transforms. Entity only composes an explicitly supplied attachment transform.
- `packages/formats/keyvalues` does not parse BSP entity blocks. Entity-lump anonymous blocks and ordered key/value pairs are a distinct syntax contract.
- `tools/playsrc` owns command orchestration and inventory generation. Applications and tools consume the Entity interface and cannot embed another entity graph, queue, hierarchy, or trigger authority.

Collision owns overlap/contact production, Movement owns linear/angular pusher trajectories and carry/rollback, and games retain grants, damage decisions, subject predicates, TF2 catapult specialization, animation sequence lookup and rules. Unofficial course zones and ruleset timers are excluded.
