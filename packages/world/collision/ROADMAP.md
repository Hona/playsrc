# Collision Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery status, coverage classification, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 30 behavior rows. The candidate inventories contain 174 items: 76 collision shape, query, filter, solid, flag, and bounds-policy items in [`inventories/shapes-and-queries.md`](inventories/shapes-and-queries.md), and 98 contents, mask, surface, displacement-flag, and shared collision-group items in [`inventories/contents-and-masks.md`](inventories/contents-and-masks.md). They contribute 0 denominator items until checked-in generators emit them and a denominator review accepts them. The current completion denominator is therefore 30 behavior rows. Acceptance of all 174 candidate inventory items without a roadmap change would make the denominator 204 items.

The denominator covers immutable collision representations and deterministic spatial queries required by Team Fortress 2, Counter-Strike: Source, and legacy Source 1 Counter-Strike: Global Offensive. It includes world brushes, transformed brush models, displacements, static props, entity boxes and custom adapters, triggers, StudioModel hitboxes, PHY convex compounds, contents, masks, surfaces, point contents, finite rays and lines, AABB and convex sweeps, overlaps, stateless geometric contacts, filtering, initial overlap, exact result identity, broad phase, narrow phase, malformed input, numerical bounds, concurrency, and bounded performance. It excludes rigid-body advancement, persistent physics contacts, player movement decisions, damage, entity lifecycle, visibility, rendering, and Source 2.

The denominator is Not accepted. Both inventories lack checked-in generators and review records; declared content-build indexes are Missing; stateless contact ownership conflicts with the current physics README; exact equal-hit ordering lacks a retained target comparison; and numeric performance budgets have not been selected.

## Inputs

- Immutable canonical map collision inputs supplied by `packages/world/map`: ordered BSP world and brush-model identities; brush planes, sides, bevel markers, contents, and surfaces; compiled displacement triangles and tags; static-prop instances; and map-wide stable identities. The collision package does not parse BSP bytes or assemble unrelated map domains.
- Immutable decoded PHY inputs supplied by `packages/formats/phy`: ordered solids, convexes, vertices, faces, game data, per-triangle material metadata, contents inputs, and source identities. The collision package does not decode PHY bytes.
- Immutable StudioModel inputs supplied by `packages/formats/studio-model`: selected hitbox set, ordered hitboxes, bones, bone contents, physics-bone indexes, surface-property identities, and validated model references. A query using hitboxes also supplies one immutable ordered bone-transform snapshot.
- One dynamic collision snapshot containing a monotonic snapshot identity and ordered records with stable entity or prop identity, enabled state, collision transform, linear and angular velocity metadata, solid type, solid flags, surrounding-bounds policy, contents, surface identity, collision-group integer, optional trigger bounds, and optional custom query adapter. Collision reads the snapshot and never advances it.
- One query request selecting exactly one operation and query shape from [`inventories/shapes-and-queries.md`](inventories/shapes-and-queries.md), a 32-bit contents mask, one trace scope, trigger selection, ordered ignored identities, an optional pure custom predicate, an optional pure game-owned collision-group predicate, and the dynamic snapshot identity.
- One required limits record containing `maxStaticShapes`, `maxDynamicShapes`, `maxConvexesPerShape`, `maxPlanesPerConvex`, `maxVerticesPerConvex`, `maxTrianglesPerShape`, `maxBvhNodes`, `maxBvhDepth`, `maxCandidateVisits`, `maxNarrowPhaseTests`, `maxOverlapResults`, `maxContactPairs`, `maxContactPoints`, `maxCustomPredicateCalls`, `maxQueryScratchBytes`, and `maxConcurrentQueries`. Every field is a non-negative integer; no build or query has an unbounded mode.
- Source-space geometry coordinates in `[-16384, 16384]`, query positions in `[-32768, 32768]`, and finite query lengths no greater than `MAX_TRACE_LENGTH = 1.732050807569 × 32768`. A query outside these bounds is Malformed and does not run broad phase.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/cmodel.h`, `trace.h`, `gametrace.h`, `bspflags.h`, `const.h`, `coordsize.h`, `worldsize.h`, `collisionutils.{h,cpp}`, `dispcoll_common.{h,cpp}`, `vphysics_interface.h`, `engine/ICollideable.h`, `engine/IEngineTrace.h`, and `engine/IStaticPropMgr.h`; `src/public/bone_setup.cpp`; `src/game/shared/collisionproperty.{h,cpp}`, `util_shared.{h,cpp}`, and `gamemovement.cpp`; and `src/game/shared/tf/tf_shareddefs.h`, `tf_gamerules.cpp`, and `tf_gamemovement.cpp` for the game-owned TF2 seams.
- Exact archive indexes, parsed collision inputs, and controlled target observations for one accepted content build each of TF2, CS:S, and legacy Source 1 CS:GO. TF2 build `24207079` and game version `10822003` supply the fixed current checkpoint inputs; CS:S and legacy Source 1 CS:GO inputs are Missing.

## Outputs

- An immutable `CollisionWorld` containing the selected content build, coordinate contract, static shape table, static broad phase, stable source associations, exact 32-bit contents, surface identities, and build diagnostics. Dynamic state is never copied into this immutable value.
- One validated dynamic collision snapshot view and deterministic dynamic broad-phase index keyed by its snapshot identity. Rebuilding or refitting this index cannot mutate the snapshot.
- A `PointContentsResult` containing the combined unsigned 32-bit contents, ordered contributing shape identities, and the selected target-compatible entity identity when that operation requests one.
- A `TraceResult` containing query identity, requested start and end, result start, fraction, optional leave fraction with an explicit validity flag, end position, plane normal and distance with an explicit validity flag, contents, displacement flags, surface name identity, surface-property identity, surface flags, hit shape, hit entity, static-prop identity, brush/model/convex/triangle feature identity, hitbox, hitgroup, physics bone, `startSolid`, `allSolid`, and `initialOverlap`.
- An `OverlapResult` containing ordered shape and feature identities with contents, surface, and entity associations. A caller-supplied maximum is enforced before adding each result; overflow returns a limit error and no partial authoritative result.
- A stateless `ContactResult` containing ordered shape pairs and bounded contact sets. Each contact set contains one oriented normal, non-negative depth, ordered points, contents on both sides, surface identities, and source feature identities. No impulse, friction state, solver constraint, or persistent contact handle is emitted.
- A structured error containing operation, query identity, snapshot identity, stable input identity, violated invariant, offending value, configured limit, and exactly one `Malformed`, `Unsupported`, `Unknown`, or `Missing` classification.

## Invariants

- All public positions, distances, bounds, planes, normals, and velocities use Source XYZ coordinates and inches. Shape construction performs no game, rendering, transport, or asset coordinate conversion.
- Every static and dynamic shape has one stable identity. Broad-phase nodes, cache slots, allocation addresses, thread schedules, and traversal stacks never become public identity or tie-break inputs.
- Contents and masks are unsigned 32-bit bitsets. Every named value in [`inventories/contents-and-masks.md`](inventories/contents-and-masks.md) retains its exact bits; bit 31 remains observable and Unknown unless a future accepted authority assigns it.
- A candidate enters narrow phase only when its enabled/solid/trigger state, query scope, ignored-identity set, contents intersection, game-owned collision-group predicate, and custom predicate all accept it in that order. A rejected candidate cannot affect result ordering or counters other than declared diagnostics.
- An AABB or hull retains caller mins and maxs. The centered broad-phase form is derived as `(mins + maxs) / 2` and `(maxs - mins) / 2`; result positions remain relative to the caller's original reference point.
- A no-hit trace has `fraction == 1`, `endPosition == requestedEnd`, `startSolid == false`, `allSolid == false`, no valid plane, and no hit identity. A non-initial hit has `0 <= fraction < 1`, `endPosition == requestedStart + fraction × (requestedEnd - requestedStart)`, and a valid unit plane facing against entry motion.
- `startSolid` means the query shape overlaps at least one accepted target at the requested start. `allSolid` means the selected target operation cannot find a non-overlapping query position on the complete requested segment. `allSolid` implies `startSolid` and `fraction == 0`.
- Leave fraction is valid only for query/shape families whose accepted target contract defines it. Invalid leave fractions are never represented as meaningful zero. When valid, `0 <= leaveFraction <= 1` and its position is derived from the original requested segment.
- Brush and displacement entry calculations use the accepted family epsilon. Source brush and displacement profiles use `DIST_EPSILON == DISPCOLL_DIST_EPSILON == 1/32` inch; box, hitbox, and PHY profiles retain their separately accepted tolerance. One family never silently borrows another family's epsilon.
- Tangency, coplanarity, shared edges, shared vertices, seams, zero motion, zero extents, thin solids, acute corners, and equal fractions have categorical outcomes in evidence. Epsilon is applied to signed separation tests and never by moving stored geometry.
- Surface name, surface-property identity, surface flags, displacement flags, contents, hit entity, static-prop identity, hitbox, hitgroup, physics bone, and feature identity come from the selected narrow-phase hit. A broad-phase bound or fallback box cannot supply final hit metadata.
- Static world geometry is tested before eligible dynamic geometry. Every remaining equal-hit choice uses the accepted stable tie order. The result is independent of insertion order except where the accepted target comparison explicitly establishes source order as observable.
- Moving geometry is queried at one supplied snapshot transform. A query never interpolates, predicts, advances, or samples an entity transform; a caller requiring a continuous relative-motion query supplies start and end transforms through the moving-geometry operation.
- Broad-phase omission of a shape whose narrow phase would pass is a failure. Broad-phase false positives are permitted and must be removed by narrow phase. Running exhaustive narrow phase over the same accepted candidates must produce the same observable result.
- Every point, scalar, plane, transform, bound, count, index, product, sum, recursion step, candidate visit, predicate call, result, contact point, and scratch allocation is validated against finite arithmetic and the required limits before use or allocation.
- A failed world build emits no `CollisionWorld`. A failed query emits no partial authoritative result. Diagnostic candidate counts and ranges cannot be consumed as collision truth.
- `CollisionWorld` and shape records are immutable and shareable. Each query owns or borrows disjoint bounded scratch state. Concurrent queries over identical world, snapshot, request, and limits produce bit-identical ordered outputs without locks that serialize read-only narrow phase.

## Ownership Exclusions

- BSP headers, lump records, game-lump records, branch layouts, compression, and lossless bytes belong to `packages/formats/bsp`. Collision consumes typed records and does not become another BSP parser.
- PHY headers, collision payloads, convex record decoding, keydata syntax, and model association belong to `packages/formats/phy`. Collision consumes validated runtime-neutral convexes.
- MDL/VVD/VTX/ANI parsing, hitbox record decoding, skeleton construction, and animation data belong to `packages/formats/studio-model`. Collision consumes selected hitbox records and supplied bone transforms.
- Map-wide model, entity, prop, displacement, material, and surface reference assembly belongs to `packages/world/map`. Material and surface-property meaning belongs to `packages/world/material`; collision retains only supplied identities and flags.
- Entity enablement, transforms, parenting, custom behavior, trigger lifecycle, touch phases, mover scheduling, rollback, blocking, and crush decisions belong to `packages/world/entity`, `packages/runtime/simulation`, and the selected game. Collision answers snapshot queries only.
- Player hull selection, ground classification, stair choice, velocity clipping, water-level decisions, movement caching, and command advancement belong to `packages/runtime/movement` and the selected game. Movement consumes collision results without redefining collision.
- Rigid-body integration, persistent contact creation and deletion, solver manifolds, friction, restitution, constraints, sleeping, and collision response belong to `packages/runtime/physics`. Collision owns only immutable shapes and stateless geometric query results after the contact-query boundary is resolved.
- Shared collision-group integers are retained by collision. `TF_COLLISIONGROUP_GRENADES`, `TFCOLLISION_GROUP_OBJECT`, `TFCOLLISION_GROUP_OBJECT_SOLIDTOPLAYERMOVEMENT`, `TFCOLLISION_GROUP_COMBATOBJECT`, `TFCOLLISION_GROUP_ROCKETS`, `TFCOLLISION_GROUP_RESPAWNROOMS`, `TFCOLLISION_GROUP_TANK`, `TFCOLLISION_GROUP_ROCKET_BUT_NOT_WITH_OTHER_ROCKETS`, TF2 team aliases, every game-specific group extension, and every group-pair decision belong to `games/tf2`, `games/css`, or `games/csgo`.
- Hitgroup damage meaning, team barriers, projectile policy, class filters, owner filters, and game-specific contents policy belong to the selected game. Collision invokes supplied pure predicates and returns identities.
- Visibility, PVS, areas, areaportals, and culling belong to `packages/world/visibility`; pixels and debug drawing belong to `packages/presentation/rendering` and tools.
- Inventory generation, collision inspection commands, captures, benchmarks, and publication belong to `tools/*` and `packages/asset-store`. Source 2 collision and physics are excluded.
