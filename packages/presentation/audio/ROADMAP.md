## Completion Denominator

The current completion denominator contains exactly the 40 Behavior Families rows below. [`inventories/script-fields.md`](inventories/script-fields.md) contains 59 candidate runtime script-field, decorator, and codec items. [`inventories/channels-and-levels.md`](inventories/channels-and-levels.md) contains 47 candidate channel, symbolic-level, and attenuation items. Candidate items contribute 0 denominator items until checked-in generators reproduce both inventories and a denominator review accepts this roadmap. Acceptance of all 106 current candidates would make the denominator 146 items.

The current target is PC audio presentation for Team Fortress 2 build `24207079` under the sound interfaces and game behavior declared by Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`. Counter-Strike: Source and legacy Source 1 Counter-Strike: Global Offensive enter this roadmap only when their Future root targets supply exact content builds, audio profiles, and game-owned event inventories. The current interface never guesses a game, content build, codec, mixer profile, or browser profile.

The denominator is Not accepted. Both inventory generators, a complete configured TF2 provider plan, exact execution bounds, current target captures, selected browser profiles, network-voice profile, accepted game and replay event producers, reviewer identity, review date, reviewed commit, and passing review record are Missing.

## Inputs

- One immutable audio-content identity containing game, content build, ordered Content provider plan, archive-index hashes, sound-definition manifest identity, soundscape manifest identity, sound-mixer identity, DSP-preset identity, sentence identity, and selected language. Every referenced document and resource is resolved by exact logical path through `packages/content`.
- Parsed KeyValues documents from `packages/formats/keyvalues` for sound-definition manifests, sound definitions, soundscape manifests, and soundscapes. Audio owns their field semantics, registry construction, duplicate and override behavior, selected-occurrence validation, and presentation runtime state; it never reparses KeyValues bytes or advances a game/network/replay producer's random-wave cycle.
- Exact bytes and provenance for accepted WAVE and MP3 resources plus an explicit selected network-voice profile. Audio validates and decodes audio-specific containers, sample metadata, loop declarations, sentence metadata, and supported encoded samples.
- One ordered `AudioEvent` stream. Each event has session identity, timeline identity, simulation tick or replay cursor when applicable, producer ordinal, audio ordinal, action (`start`, `update`, `stop`, `stop-looping`, or `reset`), game-owned event identity, sound-definition or direct-resource identity, source kind (`world`, `entity`, `local-listener`, `UI`, or `voice-peer`), source and owner identities, channel, flags, optional origin set and direction, optional parameter overrides, scheduled presentation time, and coverage classification. A definition start also carries normalized volume, pitch, and level samples plus the producer-selected original wave ordinal; Audio never derives any sample from the event, entity, voice, or resource identity.
- One ordered listener-state stream with presentation time, finite origin, finite orthonormal forward and up vectors, finite velocity when doppler input is enabled, underwater state, master gain, per-category user gains, mute state, and browser lifecycle state. State revisions are strictly increasing.
- One acoustic-occlusion callback receiving stable voice identity, listener revision, source origin set, radius, sound level, and a bounded ordered query set. It returns Collision-owned hit classifications and fractions only. Audio owns the resulting acoustic gain target and transition.
- One immutable mix profile containing sound-mixer group rules, mixer gains, ducking inputs, wet/dry routing, DSP preset graph, speaker routing, duplicate policy, spatial profile, output layout, sample rate, and every numeric tolerance used by evidence.
- One required limits value containing `maxDocuments`, `maxDocumentBytes`, `maxDefinitions`, `maxWavesPerDefinition`, `maxSoundscapes`, `maxSoundscapeCommands`, `maxSoundscapeDepth`, `maxMixerRules`, `maxMixers`, `maxDspPresets`, `maxDspNodes`, `maxResourceBytes`, `maxDecodedFramesPerResource`, `maxDecodedBytesPerResource`, `maxResidentBufferBytes`, `maxBufferedResources`, `maxStreams`, `maxStreamBufferedBytes`, `maxActiveVoices`, `maxQueuedEvents`, `maxOriginsPerVoice`, `maxSentenceWords`, `maxSentencePhonemes`, and `maxDiagnostics`. No unbounded mode exists.
- A browser adapter for the W3C Web Audio API Recommendation of 17 June 2021. The adapter supplies one `AudioContext`, state transitions, scheduling clock, buffer and stream nodes, gain and panning nodes, worklet capability, output layout, close signal, and structured operation failures without redefining Audio behavior.
- Valve Developer Community [`Soundscripts`](https://developer.valvesoftware.com/wiki/Soundscripts) and [`Soundscape`](https://developer.valvesoftware.com/wiki/Soundscape) field contracts, checked 16 July 2026. Their immutable page revisions are Unknown.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/{soundflags.h,soundchars.h,soundstartparams.h,soundinfo.h,sentence.h,eiface.h,cdll_int.h,irecipientfilter.h}`, `src/public/engine/{IEngineSound.h,SndInfo.h}`, `src/public/SoundEmitterSystem/isoundemittersystembase.h`, `src/public/{SoundParametersInternal.cpp,vaudio/ivaudio.h,soundsystem/isoundsystem.h,soundsystem/snd_audio_source.h}`, `src/game/shared/{shareddefs.h,playernet_vars.h,SoundEmitterSystem.cpp,soundenvelope.*}`, `src/game/client/c_soundscape.*`, and `src/game/server/{soundscape.*,soundscape_system.*,sound.cpp,ai_sentence.*}`.

## Outputs

- One immutable `AudioRegistry` containing stable sound-definition, wave, soundscape, mixer, DSP, sentence, channel, level, attenuation, decorator, and codec identities; declaration and override traces; exact resource requests; provenance; and one coverage classification per entry.
- One deterministic event result containing accepted action, selected definition and original wave ordinal, sampled volume, pitch, sound level, resolved channel, scheduled start offset, audience decision, resource state, active-voice identity, replaced or suppressed identities, and structured diagnostics.
- One revisioned active-voice set. Each voice exposes source, owner, channel, selected resource, decoder, stream or buffer mode, frame cursor, loop point, start and stop times, source transform, listener revision, distance gain, pan gains, occlusion gain, mixer groups, wet/dry sends, DSP selection, browser-node state, and terminal reason.
- One soundscape state containing active identity, expansion trace, looping layers, random schedules, local-position bindings, inherited overrides, ambient state, selected mixer and DSP inputs, crossfade targets, and reset reason.
- Canonical decoded audio containing source identity and provenance; codec; channel count; sample rate; frame count; canonical signed float planes; loop start; duration; sentence metadata; and exact bytes charged to resource budgets.
- A bounded observation stream keyed by session, event, voice, definition, wave, source, channel, listener revision, browser state, resource state, sample cursor, gain stages, mixer groups, soundscape layer, and error code. Observation cannot change selection, timing, or mix output.
- Structured `Malformed`, `Unknown`, `Unsupported`, `Missing`, capacity, permission, suspended, closed, cancellation, and browser-operation failures naming the operation, stable input identity, violated invariant, source location when present, required value, available value, and last committed audio-state revision.

## Invariants

- Audio is presentation-only. It consumes explicit world, gameplay, networking, and replay events and never advances gameplay, replay, entity, collision, camera, or product state.
- Registry construction is deterministic over supplied parsed documents, provider results, profile, and limits. ASCII-insensitive identities retain original spelling and provenance. Manifest order, document order, repeated fields, random-wave order, override order, and soundscape command order remain observable.
- One audio event is applied atomically in `(timeline identity, simulation tick or replay cursor, producer ordinal, audio ordinal)` order. A rejected event creates no voice, consumes no random selection, and changes no prior voice.
- Audio consumes only producer-supplied deterministic samples from named slots. A definition start carries normalized volume, pitch, and level samples plus an original wave ordinal selected by its game/network/replay owner in target order. Future Audio-owned soundscape schedules consume first-delay, next-delay, wave, volume, pitch, level, and random-position slots in fixed order. No process randomness or wall clock is read.
- Random-wave availability and selection occur before a definition-start event crosses its owner seam. Audio validates and resolves the supplied original ordinal without maintaining a second no-repeat cycle, resampling around a missing resource, or changing the selected occurrence after a failed start.
- Direct resource and sentence identities retain their decorator prefix and undecorated token. Audio constructs one exact `sound/<token>` Content request for file resources and never scans, changes extensions, strips directories, or substitutes another resource.
- A voice starts only after definition resolution, variation, audience evaluation, resource validation, capacity disposition, and browser-node construction all succeed. A failed start publishes no active voice and retains all prior voices.
- Start, update, stop, replacement, duplicate suppression, natural end, loop end, reset, browser close, and capacity eviction are distinct terminal or transition reasons. Every voice reaches exactly one terminal reason and releases each browser and decoder resource once.
- Source transforms and listener transforms are immutable per revision. Re-spatialization consumes an explicit later revision. A missing entity transform never becomes world origin, local-listener origin, or the previous entity transform.
- Distance, directional, stereo, radius, occlusion, mixer, user, master, wet/dry, DSP, ducking, and output-layout gains are separately observable. Their product cannot feed back into gameplay relevance, network recipients, collision, or source-event production.
- `SNDLVL_NONE` is non-attenuated. Ambient and declared non-spatial sounds are not panned or occluded. Positioned sounds preserve source direction, local radius, and output layout; stereo decorators determine channel interpretation before output panning.
- Collision owns geometric queries and results. Audio may request only the accepted bounded acoustic query set and may use only returned hit data; it cannot traverse BSP, trace rays, inspect materials, or create collision truth.
- Soundscape changes clear random schedules, retarget prior loops, and create the new expansion atomically. Recursion depth, local-position indexes, inherited position overrides, missing child identities, and unavailable local positions are validated before a layer starts.
- Replay reset or seek reset stops all replay-timeline voices and soundscape schedules atomically. Audio never re-emits skipped transient events or infers a sound from entity disappearance or snapshot differences.
- A suspended browser context advances no Audio-owned presentation clock. Resume requires an explicit application-provided permission result. A closed context is terminal and rejects every later resource or playback operation.
- Every document, definition, reference, decoder input, decoded frame, resident byte, stream byte, voice, queued event, soundscape command, recursion step, mixer rule, DSP node, origin, sentence item, browser node, and diagnostic is charged before allocation or mutation. Capacity failure never selects an undocumented victim or silently drops a required event.
- No unknown field, codec, channel, level, decorator, event action, DSP identity, browser state, or game-specific mapping selects a default implementation, compatibility branch, placeholder sound, silent substitute, or stale artifact.

## Ownership Exclusions

- `packages/formats/keyvalues` owns KeyValues tokenization, structure, source spans, and structural errors. Audio consumes successful parsed documents and owns only audio semantics.
- `packages/content` owns provider eligibility, provider order, exact logical-path resolution, active-map PAK precedence, bytes, caching, and provenance. Audio owns resource-token classification, exact dependency requests, audio decoding, and playback resources.
- `games/<game>` owns the decision that a game-specific state transition or game event emits a sound, the mapping to a generic Audio event, source-owner identity, and every game-specific channel value at or above `CHAN_USER_BASE`. Audio owns definition resolution and presentation after that event exists.
- `packages/runtime/networking` owns sound-message and voice-message wire framing, bounds, ordering, and delivery. Audio owns typed sound events and the selected encoded voice profile after Networking hands off complete payloads.
- `packages/runtime/replay` owns replay progression, event cursors, pause, seek, reset ordering, and event history. Selected games own recorded-message meaning. Audio owns only playback state produced from ordered replay audio events.
- `packages/world/entity` and the selected game own `env_soundscape`, trigger, source-entity, speaker-entity, enable/disable, range, visibility, and local-position entity state. Audio owns soundscape documents, expansion, schedules, ambient layers, mixer inputs, and transitions after receiving explicit active soundscape state.
- `packages/world/collision` owns traces and acoustic-blocking hit results. `packages/world/visibility` owns PVS and PAS queries. Audio owns no geometry or recipient relevance and owns acoustic gain only from explicit supplied results.
- `packages/presentation/rendering` and applications own camera selection and product views. They supply listener transforms but cannot create, stop, replace, or mix voices.
- Applications own user settings UI, gesture acquisition, tab and route lifecycle, concrete browser creation, output-device selection, and product error presentation. Audio owns Web Audio graph resources and state transitions behind its adapter.
- Close captions, localized caption presentation, haptics, MIDI synthesis, authored movie audio, recording, and export containers are outside this denominator. Sentence timing and phoneme metadata remain Audio outputs for their separate consumers.
