## Completion Denominator

The current completion denominator contains exactly the 42 Behavior Families rows below. [`inventories/operators.md`](inventories/operators.md) contains 95 Candidate operator items. [`inventories/tf2-systems.md`](inventories/tf2-systems.md) contains 12,651 Candidate system-definition items available from the configured TF2 content build; nine selected PCF references are Missing, so the complete TF2 system-item count is Unknown. Neither inventory has a checked-in generator or an Accepted review. Both inventories therefore contribute 0 denominator items, and the current completion denominator is 42 items.

The denominator is Not accepted. It targets runtime-neutral Source 1 particle definition semantics and presentation-state advancement for TF2 content build `24207079`. Counter-Strike: Source and legacy Source 1 Counter-Strike: Global Offensive enter this leaf denominator only when their root targets are activated with exact content identities and generated inventories. Source 2 particle resources are excluded.

## Inputs

- One ordered particle-manifest document containing exact `file` entries, source order, precache marker, logical identity, provenance, and source hash. The global identity is `particles/particles_manifest.txt`; a selected map checks `particles.txt` in its active BSP PAK, `maps/<map>_particles.txt` in that PAK, then the exact `maps/<map>_particles.txt` GAME request.
- Ordered caller-supplied Source 1 binary-v2/PCF-v1 byte sequences with exact logical path, provenance, and content hash. Particle decodes this one target PCF profile; it does not read providers, archives, directories, or generic DMX formats.
- One immutable definition environment containing target game, content build, selected map identity, ordered provider plan, PC particle profile, and accepted operator registry identity. No environment value is inferred from the browser or GPU.
- One ordered event stream. Events are `create`, `set-control-point`, `set-control-point-parent`, `start-emission`, `stop-emission`, `restart`, `set-dormant`, `destroy`, and `reset`. Every event carries stable event identity, presentation timestamp, source order, effect identity, and all command-specific parameters.
- A `create` event supplies one definition name or UUID, explicit random seed, start timestamp, zero through 64 control-point snapshots, and optional owner identity. Name lookup ignores ASCII case; UUID lookup is exact.
- A control-point snapshot supplies index, current and previous position, forward/right/up basis, velocity, radius, density, duration, parent index, optional controlling-object identity, and the timestamp at which the snapshot is valid. Every scalar and vector is finite.
- An explicit advancement request containing prior presentation timestamp, target timestamp, requested elapsed duration, fixed-step policy, first-frame state, reset state, and update-bounds policy. Wall-clock time is never read.
- Immutable Material output for every definition material reference and typed VTF particle-sheet sequences for every selected material texture. Material and VTF retain provenance and source hashes.
- Query adapters for finite collision traces; controlling-object bounds, hitboxes, transforms, and point containment; lighting samples; camera position and basis; local-viewer snapshot; and pixel visibility. Each request and result carries stable identity and presentation timestamp.
- A required limits record containing `maxManifestEntries`, `maxDefinitions`, `maxDefinitionDepth`, `maxAttributesPerElement`, `maxOperatorParameters`, `maxSystems`, `maxEffects`, `maxChildrenPerSystem`, `maxChildDepth`, `maxParticlesPerSystem`, `maxParticlesTotal`, `maxControlPoints`, `maxOperatorsPerCategory`, `maxConstraintPasses`, `maxSubsteps`, `maxQueriesPerAdvance`, `maxEventsPerAdvance`, `maxRenderItems`, `maxOwnedBytes`, and `maxDiagnostics`. The package defines no unbounded mode.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/particles/particles.h`, `src/public/movieobjects/dmeparticlesystemdefinition.h`, `src/game/shared/{particle_parse,particle_property,particlesystemquery}.{h,cpp}`, `src/game/client/{particles_new.cpp,c_particle_system.cpp}`, `src/game/server/particle_system.{h,cpp}`, current TF2 particle consumers under `src/game/{client,shared,server}/tf`, and `src/lib/public/linux64/particles.a` with SHA-256 `2700ff6cecb972db32b2b01a790cb28ccab2775db383d2e7ea6a32d9cdbb1f9e`.

## Outputs

- An immutable `ParticleDefinitionRegistry` containing selected manifest trace; name and UUID indexes; definition source and shadow trace; typed system attributes; ordered renderer-data, operator, initializer, emitter, force, constraint, and child declarations; material/model dependencies; and one coverage classification per field and declaration.
- A mutable presentation-only `ParticleWorld` advanced exclusively through ordered events and explicit advancement requests. It contains effect, system, child, operator-context, control-point, random-stream, particle, bounds, and lifecycle state.
- Per-particle current and required initial values for position, prior position, life duration, radius, roll, roll speed, RGB tint, alpha, creation time, primary sequence, trail length, particle ID, yaw, secondary sequence, hitbox index, hitbox-relative position, alternate alpha, trace endpoints, trace fraction, trace normal, and target control-point index.
- Per-system state containing definition identity, effect identity, parent and ordered children, local time, prior step, first-frame state, active/allocated counts, next particle ID, explicit seed and sample counters, operator contexts, emission/dormancy state, render and simulation frame counts, current bounds, center, and completion decision.
- Ordered query requests and returned-result trace. Particle state changes only from supplied results; adapters retain ownership of collision, models, entities, lighting, camera, and pixel-visibility truth.
- An immutable `ParticleRenderOutput` containing system and particle identities; renderer-data identity and parameters; material identity; current/prior positions; radius; roll and yaw; tint; combined alpha; sequence and secondary sequence; sampled UV rectangles and blend; trail length; sort key and stable tie identity; bounds; culling descriptor; visibility scale; model reference and transform when required; and required primitive kind. It contains no GPU handle, shader module, draw command, browser object, or resource-lifetime policy.
- Stable diagnostics containing operation, event and effect identity, definition logical path and hash, DMX element UUID, system and operator identity, field, source span, query identity, configured limit, coverage classification, and no substitute effect or state.

## Invariants

- Particle is presentation state. Its advancement, collision queries, bounds, culling descriptors, and output cannot mutate gameplay authority or replay authority and cannot create a gameplay event.
- Registry construction and advancement are deterministic over supplied bytes, typed documents, registries, events, timestamps, seeds, query results, material state, sheet data, and limits. Ambient process randomness, pointer values, wall-clock time, filesystem access, provider selection, GPU queries, and mutable game state are forbidden inputs.
- A manifest is processed in source order. The active map PAK precedes external providers only through Content. A selected malformed, unreadable, changed, or over-limit entry fails at that entry; Particle never searches another provider or substitutes an error definition.
- Definition names and operator identities compare without ASCII case while source spelling remains observable. Accepted source spellings normalize only through the generated operator inventory. An unknown name never selects a prefix, edit-distance match, similarly named system, or placeholder.
- A name-indexed definition loaded later replaces the earlier definition for subsequent creation and records the complete shadow trace. A definition declaring UUID-only lookup enters only the exact UUID index. Name and UUID identities are never conflated.
- The semantic graph retains all 29 encountered system fields and every unknown field. Missing declared fields use only the accepted field-qualified default. Duplicate, wrong-typed, non-finite, unknown, and out-of-range fields receive explicit classifications and never disappear during flattening.
- The particle attribute universe has 32 slots; the 22 named slots listed under Outputs have accepted semantics and the remaining ten slots stay unassigned. Vector, scalar, integer, normalized, angle, current, and initial storage kinds never alias across semantic fields.
- A PC particle system accepts at most 5,000 active particles and 64 control points. Lower caller limits take precedence. A definition count below one, a negative initial count, an out-of-range control point, and every allocation overflow are handled before publication or mutation.
- Every collection has one explicit seed. Particle IDs increase within that collection. Random samples are functions of seed, particle ID or system sample identity, operator sample offset, and declared sample ordinal; execution scheduling and render-frame partitioning cannot change them.
- Operator strength is derived from the system-local timestamp and the declaration's fade-in, fade-out, and oscillation fields. Invalid intervals are classified by the operator contract; no global coercion silently changes every operator.
- First-frame advancement runs pre-emission operators, creates bounded initial particles, applies initializers, captures required initial attributes, and does not run an ordinary positive-time substep. A positive substep runs pre-emission operators, emitters, initializers for newly emitted particles, post-emission operators, child systems, previous-control-point update, and bounds update in that order.
- Initializers claiming an exclusive attribute run in declaration order until that attribute is initialized. Modifier initializers run in a second declaration-ordered tier. Unclaimed required values come from field-qualified constants; every origin remains observable.
- Force generators accumulate in declaration order for the movement operation that consumes them. Constraints prepare once per substep, iterate non-final declarations in source order for at most the declared pass limit, and run final constraints once in source order.
- One advancement substep is positive and no greater than the definition's accepted maximum step. One request executes at most the required `maxSubsteps`; the output reports consumed and unconsumed duration. Time never moves backward without a reset event.
- Control-point position is interpolated between prior and current snapshots for an operator timestamp; basis, velocity, radius, density, duration, object identity, and parent are sampled through their declared contracts. Parent chains are finite, acyclic, and evaluated parent before child.
- Setting control-point state on a root propagates the same external state to all instantiated children before their next advancement. An operator-owned control-point write remains scoped to the declared collection unless that operator's accepted contract explicitly writes child state.
- Child declarations retain source order, name-or-UUID lookup mode, and non-negative delay. Children instantiate with the parent, keep separate particle, random, context, time, bounds, and completion state, and cannot create a definition cycle.
- Graceful stop prevents the selected emitter scope from creating new particles and permits existing particles and children to finish. Immediate stop removes all selected particles and children in the same event. Dormancy, restart, replacement, reset, and destruction are distinct commands.
- A system is finished only after first-frame work, when it is not dormant, has no active particles, every emitter reports that it cannot create another particle, and every child is finished. Finishing never invents a destroy event; the caller consumes the completion result.
- Particle death is applied after each operator that can kill. Stable-order renderers compact surviving attributes without reordering; other systems may fill holes from the tail. Current and retained initial attributes move together.
- Bounds enclose every active particle position expanded by the definition bounds, every read control point after first-frame stabilization, and every child bound. Empty bounds are explicitly invalid and never become an infinite or origin-sized visible box.
- Material references, VTF sheet selection, model references, collision masks and groups, lighting inputs, local-viewer inputs, and pixel-visibility inputs remain typed dependencies. Missing dependencies return their exact classification and never become a white texture, unit frame, no-hit trace, full visibility, or substitute model.
- Definition culling, no-draw sleep, cull replacement, camera-control-point suppression, visibility scaling, and render sorting consume explicit camera and visibility inputs. They change only presentation advancement or `ParticleRenderOutput`; they cannot suppress events or alter gameplay/replay state.
- Renderer-data operators produce runtime-neutral primitives. Rendering owns GPU batching, resource upload, pass selection, shader execution, framebuffer reads, draw calls, and pixels and cannot reinterpret an Unsupported renderer-data operator.
- Every encountered system, field, operator, child, material, model, query, and event is exactly one of Handled, Intentionally inert, Unsupported, Malformed, Unknown, or Missing. Registry and advancement failure return no substitute system and no partially published authoritative result.
- Every count, index, depth, elapsed duration, substep, query, append, multiplication, addition, allocation, and diagnostic is checked against integer range and the supplied limit before use.

## Ownership Exclusions

- Particle owns bounded decoding of Source 1 binary-v2/PCF-v1 bytes because this encoding is the runtime input to particle semantics. A future generic DMX owner may own other encodings, formats, editing operations, and serialization, but Particle does not depend on that owner or duplicate those broader behaviors.
- `packages/formats/keyvalues` owns manifest syntax and ordered KeyValues trees. Particle owns the `file` field schema, precache marker, manifest ordering, and definition-load trace.
- `packages/content` owns logical-path validation, provider order, active-map PAK precedence, exact byte retrieval, caching, and provenance. Particle requests exact manifest, PCF, material, texture, and model identities and never scans archives or directories.
- `packages/world/material` owns resolved material semantics and material-level animation. `packages/formats/vtf` owns VTF resources and typed particle-sheet payloads. Particle owns particle sequence selection, sheet-time sampling, and UV render data.
- `packages/formats/studio-model` and the selected entity/game owners own model, bone, attachment, and hitbox snapshots. Particle owns only query requests, returned-snapshot consumption, particle-local hitbox fields, and control-point state.
- `packages/world/collision` owns traces, masks, contents, fractions, planes, and hit results. Particle owns collision-query construction from operator state and applying returned results to presentation particles.
- `games/tf2` owns event-to-effect selection, vision-filter substitutions, TF2 attachment selection, team/custom color derivation, collision-group mapping, and all gameplay/projectile/entity decisions. Particle receives an already selected definition identity and typed event parameters.
- `packages/runtime/replay` owns recorded timeline, seeking, reset position, and ordered recorded events. Particle consumes reset plus create/control/stop events and never infers an explosion, trail, or stop from entity disappearance.
- `packages/presentation/rendering` owns camera production, general frustum and visibility candidate selection, pixel visibility, GPU resources, draw submission, lighting presentation, framebuffer dependencies, sorting between presentation domains, and pixels. Particle owns its bounds, particle-local ordering, culling descriptors, and runtime-neutral render data.
- Applications own presentation clocks, pause policy, reset requests, quality configuration, and browser lifecycle. Tools own manifest/registry/content inventory generation and target trace orchestration.
