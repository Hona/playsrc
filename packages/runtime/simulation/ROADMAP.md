# Simulation Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines gameplay authority, simulation tick, delivery status, coverage classification, inventory, snapshot evidence, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 36 behavior rows. [`inventories/tick-phases.md`](inventories/tick-phases.md) contains 18 candidate phase items and contributes 0 denominator items until a checked-in generator emits it and a denominator review accepts this roadmap. The current completion denominator is therefore 36 items. Acceptance of all 18 phase items without a roadmap change would make the denominator 54 items.

The denominator covers one deterministic gameplay authority from immutable composition through map load, normalized command admission, fixed-tick advancement, phase scheduling, events, complete snapshots, faults, and shutdown. It includes authoritative and speculative execution of the same transition implementation. It excludes domain behavior scheduled by Simulation, wall-clock pacing, network transport, replay advancement, and presentation.

The denominator is Not accepted. No Simulation implementation, generated phase inventory, evidence record, or review record exists. The public Collision and Physics contracts also disagree on ownership of stateless geometric contacts versus persistent solver contacts; the contact/trigger phase row is Blocked on that boundary.

## Inputs

- One immutable `SimulationConfiguration` containing a canonical map identity and content hash; one game identity; one game-owned ruleset identity; one ordered phase-participant manifest and SHA-256; the exact binary32 tick-interval bits; a 32-byte root random seed; `stateHash` equal to `none` or `sha256`; an authority role equal to `authoritative`, `speculative`, or `evidence`; and every required limit. No field has a default and no configuration value can change after successful construction.
- One immutable canonical map and initial world values supplied through current Map, Entity, Collision, Visibility, Movement, and Physics interfaces. Every supplied value names its owner, current interface identity, map identity, content hash, and coverage classification.
- Exactly one game adapter and one adapter for a ruleset owned by that game. Each adapter declares stable participant identities, dependency edges, phase memberships, snapshot section identity, command schema identity, command validation, missing-command policy, paused-command policy, random-stream declarations, and lifecycle hooks. Duplicate identities, cross-game rulesets, cycles, or undeclared callbacks are invalid.
- Ordered `CommandBatch` values. A batch contains one stable batch identity, producer identity and sequence, and at most `maxCommandsPerBatch` commands. Each command contains stable player identity, unsigned command number, requested simulation tick, payload schema identity, exact payload bytes, every command-scoped random seed, and backup/missing metadata when applicable.
- An integer `advanceTicks` in `1..=maxAdvanceTicksPerCall` for normal advancement. Wall-clock elapsed time, render delta, network arrival time, and host callback count are not Simulation inputs.
- One required limits record containing `maxPlayers`, `maxPhaseParticipants`, `maxAdvanceTicksPerCall`, `maxQueuedCommandBatches`, `maxQueuedCommands`, `maxCommandsPerBatch`, `maxCommandsPerPlayerPerTick`, `maxCommandLeadTicks`, `maxPhaseRecordsPerTick`, `maxEventsPerTick`, `maxSpawnRequestsPerTick`, `maxDeleteRequestsPerTick`, `maxSnapshotBytes`, `maxSnapshotsRetained`, and `maxDiagnostics`. Every value is a positive integer; no operation has an unbounded mode.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/{const.h,globalvars_base.h,eiface.h}`; `src/game/shared/{shareddefs.h,usercmd.h,usercmd.cpp,igamesystem.h,igamesystem.cpp,gamerules.h,gamerules.cpp,baseentity_shared.cpp,util_shared.cpp}`; `src/game/server/{gameinterface.h,gameinterface.cpp,world.cpp,entitylist.cpp,player.h,player.cpp,player_command.h,player_command.cpp,physics_main.cpp,physics.cpp,cbase.cpp,eventqueue.h}`; `src/game/client/{prediction.h,prediction.cpp,c_baseentity.h,in_main.cpp}`; and TF2 scheduling consumers in `src/game/server/tf/{tf_client.cpp,tf_player.cpp,tf_projectile_rocket.cpp}` and `src/game/shared/tf/{tf_gamerules.cpp,tf_weaponbase.cpp,tf_weapon_rocketlauncher.cpp,tf_weapon_grenade_pipebomb.cpp}`.

## Outputs

- One `SimulationSession` in exactly one state: `Loading`, `Ready`, `Advancing`, `Paused`, `Faulted`, or `Closed`. `Advancing` is observable only through phase records and cannot accept a concurrent mutating call.
- An immutable `SimulationIdentity` equal to SHA-256 of the canonical configuration, map, game, ruleset, phase-manifest, command-schema, and initial-state identities. Machine paths, allocation addresses, wall-clock values, authority role, and runtime type do not enter this identity.
- One `AdvanceBatch` containing every completed tick identity in order, the accepted/synthesized/rejected command disposition for each player slot, ordered phase records, ordered emitted events, the latest completed snapshot identity, and a structured result. A multi-tick call commits completed earlier ticks even if a later tick faults.
- One immutable `SimulationEventBatch` per completed transition. Every event contains simulation identity, tick, transition ordinal, phase identity, global event sequence, producer identity, producer-local sequence, event-kind identity, and owner-defined payload bytes.
- One complete immutable `SimulationSnapshot` after map load and after every completed normal or paused transition. It contains simulation identity, snapshot identity, tick, transition ordinal, gameplay time, phase-manifest identity, pending commands, event cursor, deterministic random state, and one owner-tagged length-delimited section for every phase participant.
- A `SnapshotIdentity` equal to `{simulationIdentity,tick,transitionOrdinal}`. Tick starts at zero after map load. Transition ordinal starts at zero and increments after every committed normal tick or paused command transition; a normal tick increments tick exactly once.
- When configured, lowercase SHA-256 of canonical complete snapshot bytes excluding the hash field itself. Hash absence under `stateHash: none` is explicit and never represented by an empty digest.
- Structured errors containing session state, operation, simulation identity when available, tick, transition ordinal, phase identity when applicable, batch/command/player/producer identity, stable code, violated invariant, offending value, configured limit, and one coverage classification when the error concerns classified input.

## Invariants

- One authoritative session is the only object permitted to mutate gameplay state for a session identity. A speculative or evidence session runs the same transition implementation but cannot emit an authoritative capability or substitute its state for authoritative state without Networking-owned reconciliation.
- Gameplay scheduling uses unsigned 64-bit integer ticks. Initial map state is tick zero; a normal transition commits exactly `currentTick + 1`; overflow or configured lifetime exhaustion faults before phase execution. No tick is skipped, merged, repeated, or advanced by a render frame.
- The tick interval is immutable, finite, positive, and within `0.001` through `0.1` seconds. TF2 selects the exact binary32 `0.015` value. Gameplay time is represented canonically as `{tick,intervalBits}`; a required binary32 seconds value is computed by one round-to-nearest-ties-to-even binary32 multiplication of tick converted to binary32 by interval.
- Every normal tick invokes all 18 accepted phases exactly once and in inventory order. A phase cannot call a prior phase, recursively advance Simulation, publish a partial snapshot, or observe output from a later phase.
- The phase-participant order is a total order derived at construction from explicit dependency edges, phase order, and stable participant identity. Registration timing, hash-map order, allocation address, thread schedule, message arrival within an accepted batch, and runtime language cannot affect it.
- Tick begin freezes the selected command set, player order, eligible entity work list, participant list, and starting random state. Work created during a tick can affect only later declared phases and cannot retroactively enter a frozen earlier work list.
- Command-batch admission is atomic. Exact duplicate batch or command bytes are idempotent and enqueue once. Reuse of an identity with different bytes is `CommandConflict`. A late command is `LateCommand`; a command beyond `maxCommandLeadTicks` is `LeadExceeded`. Any rejected batch leaves every queue and sequence unchanged.
- Commands execute by requested tick, then stable player identity, then unsigned command number, then producer identity and sequence. The selected game policy converts every missing slot exactly to a declared backup, repeated-last, neutral, null, or no-command disposition before player execution; callers cannot choose a policy per batch.
- A command scope activates only that command's player identity, time base, and random seeds. It is cleared before the next command even after a command-owned rejection. Persistent random streams are separately named and snapshotted; no random draw reads wall clock, process seed, thread identity, or ambient global state.
- Movement, physics, entity, game, and ruleset operations receive immutable phase inputs and return bounded transition batches. They cannot retain a mutable reference into another owner or advance themselves outside Simulation's invocation.
- Entity I/O queue state and dispatch remain Entity-owned. Simulation supplies one tick/time and ordered external records, invokes the Entity service phase once, and preserves Entity's due-time, equal-time, reentrant, and deletion results in the global phase/event order.
- Spawn allocation requested during a phase is visible only at the declared later boundary returned by Entity or the selected game. A spawned object cannot join an already frozen work list. Deletion marking removes lookup and future-work participation at the owner-defined point; storage release and stale-handle invalidation complete no later than the lifecycle-finalize phase.
- A successful tick publishes no state before game/ruleset finalize, Entity quiescence, lifecycle finalization, event sequencing, snapshot serialization, size validation, and optional hashing all succeed. A failed tick publishes neither a partial snapshot nor partial event batch.
- Canonical snapshots order sections by phase-participant identity, encode integers and binary32 values by one declared byte order and bit representation, length-prefix variable bytes, preserve owner-declared sequence order, and reject non-finite or unclassified values not explicitly allowed by the owner contract.
- Restore constructs a new session against the identical configuration and participant identities. It validates every section and bound before state publication; success reproduces the next transition byte-for-byte, and failure publishes no session. An active authoritative session never rewinds in place.
- Normal `advance(n)` while Paused returns `Paused` without consuming commands, ticks, events, random draws, or snapshot capacity. An explicit paused-command operation uses the game-declared inertization policy, zero gameplay frame time, no normal tick phases, unchanged tick, and one incremented transition ordinal if it commits state.
- Every queue insertion, participant call, event, phase record, spawn/delete request, snapshot byte, retained snapshot, diagnostic, and tick is charged against the immutable limits before allocation or mutation. Truncation is never a successful bounded result.

## Ownership Exclusions

- `packages/runtime/movement` owns ground, air, water, ladder, crouch, jump, stair, velocity, hull, and movement-result behavior. Simulation owns command-stage placement and consumes one bounded movement transition.
- `packages/runtime/physics` owns rigid bodies, integration, persistent contacts, solver manifolds, constraints, response, and sleeping. `packages/world/collision` owns immutable shapes, traces, sweeps, overlaps, and stateless geometric contact queries after the recorded contact-boundary conflict is resolved.
- `packages/world/entity` owns handles, lifecycle state, hierarchy, I/O, due-event queue, generic trigger-contact state, generic logic, and Entity snapshots. Simulation owns the tick and invocation boundary around those operations.
- `games/<game>` owns command payload meaning and validation beyond the common envelope, player state, game movement differences, classes, items, weapons, projectiles, damage, game entities, random algorithms, game rules, replicated fields, prediction fields, and game event payloads.
- `games/<game>/rulesets/<ruleset>` owns mode lifecycle, objectives, scoring, spawning restrictions, completion, and mode state transitions. Simulation invokes exactly one selected ruleset and never supplies a generic mode implementation.
- `packages/runtime/networking` owns command and snapshot wire encoding, acknowledgements, recipient selection, replication, prediction reconciliation, rates, transport queues, and backpressure. Network send cadence cannot alter Simulation's completed tick sequence.
- `packages/runtime/replay` owns recorded-state timelines, seeking, replay snapshots, and replay events. Replay never invokes Simulation to reconstruct authoritative recorded state.
- Presentation packages own interpolation, animation, particles, audio, visibility-driven culling, and pixels. Simulation events and snapshots contain no presentation-only authority and rendering cannot submit a gameplay mutation except through a declared command producer.
- Applications own wall-clock pacing, workers/processes, session placement, user input capture, and product policy. They call the coarse Simulation interface and cannot embed another gameplay loop, command scheduler, domain phase, or snapshot authority.
- Tools own inventory generation, phase tracing, controlled captures, benchmarks, and inspection. The inspector can read snapshots/events and cannot mutate a live authority.

## Exit Criteria

Simulation is Complete only when all of these predicates pass:

- All 36 behavior rows are Ready.
- The tick-phase inventory is generated, current, Accepted, and contains exactly 18 accepted items with one owner and one evidence-capable observable contract per item.
- Lifecycle, composition, map load, tick/time, commands, missing-command policy, pause, every phase, events, random state, snapshots, restore, hashes, faults, and shutdown satisfy their declared comparisons.
- Exact game command schemas, missing/paused policies, random declarations, snapshot sections, and pre/post/finalize hooks are accepted for every selected game and ruleset.
- Every multi-tick result equals repeated one-tick results through the same current interface, including failure at an intermediate tick.
