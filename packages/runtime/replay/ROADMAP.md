# Replay Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery statuses, coverage classifications, replay authority, presentation state, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 20 behavior rows. [`inventories/replay-state-families.md`](inventories/replay-state-families.md) contains 40 candidate replay-state items and contributes 0 denominator items until a checked-in generator emits it and a denominator review accepts this roadmap. The current completion denominator is therefore 20 behavior rows. Acceptance of all 40 inventory items would make the denominator 60 items.

The denominator covers one bounded decoded recorded-state timeline for each opened DEM: explicit decoder selection, sign-on and setup state, ordered record application, entity state, events, tick identities, playback controls, indexes, checkpoints, reconstruction, snapshots, and presentation inputs. It never advances gameplay from user commands. DEM container parsing, network codec semantics, game-owned message meaning, presentation simulation, rendering, and product controls remain outside Replay.

The current target is Team Fortress 2 profile `tf2-demo3-net24` from the Demo candidate inventory and one TF2-owned recorded-state decoder. Counter-Strike: Source and legacy Source 1 Counter-Strike: Global Offensive enter this roadmap only when their Future root targets activate exact Demo, Networking, and game-decoder authorities; the current interface never adds a compatibility branch or guesses another profile.

The denominator is Not accepted. The inventory generator, accepted Demo and recorded-state decoder contracts, controlled target captures, consistent game-semantics ownership statement, and recorded-replay application owner are Missing.

## Active Deterministic-Replay Checkpoint

This checkpoint implements one generic recorded-operation Replay authority over the TF2 demo/network profile: lifecycle, atomic authoritative state application, distinct command/server/cursor domains, complete record indexing and checkpoints, exact seek/rewind, pause/rational-rate/step controls, interpolation inputs, snapshot/restore identity validation, deterministic continuation, bounded work, and explicit zero-gameplay-call instrumentation. TF2 field/message meaning remains supplied by a typed game decoder; this package neither invents that meaning nor invokes Simulation. The selected generic checkpoint is Ready. TF2 decoder production and application integration remain separate blocked owners.

## Inputs

- One immutable successful Demo value containing its source identity and content hash, explicit protocol-profile identity, exact header metadata, ordered records, record ordinals, command ticks, slots, source ranges, packet metadata, payload bytes, and terminal record. Replay never opens raw DEM bytes and never repairs a failed Demo parse.
- One explicit selected-game identity and one immutable `RecordedStateDecoder` identity. The current denominator accepts only TF2. The decoder composes the shared network codec with the selected game's data-table bindings, string-table meanings, entity classes, field schemas, game events, audio mappings, particle mappings, and snapshot state. Selection is caller-supplied; Replay never infers a game from a directory, map, server, file name, or encountered class.
- Decoder operations from a closed union: sign-on transition; tick declaration; data-table replacement; string-table creation or mutation; baseline replacement; entity creation, deletion, or field patch; game event; audio event; particle event; classified console-command effect; intentionally inert record; and terminal transition. Every operation carries outer-record ordinal, inner-message ordinal, decoder-emission ordinal, source range, command tick, optional server tick, coverage classification, and decoder identity.
- Ordered playback calls: advance by a non-negative integer nanosecond duration, set positive rational rate, pause, resume, signed tick step, seek to a `ReplayCursor`, seek to a server tick, read authoritative snapshot, read presentation snapshot, and read an event range. Calls execute serially; concurrent mutation is rejected.
- One required replay-limits value containing `maxResidentBytes`, `maxIndexEntries`, `maxIndexBytes`, `maxCheckpointCount`, `maxCheckpointBytes`, `checkpointIntervalTicks`, `maxSeekRecords`, `maxEntities`, `maxFieldsPerEntity`, `maxDataTables`, `maxStringTables`, `maxStringsPerTable`, `maxStringUserDataBytes`, `maxEvents`, `maxEventsPerTick`, `maxEventPayloadBytes`, `maxSnapshotBytes`, `maxDiagnostics`, `maxStepTicks`, `maxRateNumerator`, and `maxRateDenominator`. Every field is a non-negative integer, the interval and rate bounds are positive, and no unbounded mode exists.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/demofile/demoformat.h`, `src/public/{cdll_int.h,inetmsghandler.h,iclientnetworkable.h,networkstringtabledefs.h,client_class.h,dt_recv.h,igameevents.h}`, `src/common/replay/{ireplaydemoplayer.h,ireplayperformancecontroller.h,replay.h}`, and `src/game/client/{interpolatedvar.h,c_baseentity.cpp,cdll_client_int.cpp,replay/replayperformanceplaybackhandler.cpp,tf/tf_replay.cpp}`.

## Outputs

- One `ReplaySession` with immutable source, protocol-profile, selected-game, shared-codec, game-decoder, limits, and index identities; lifecycle state `Opening`, `Signon`, `Ready`, `Ended`, or `Failed`; orthogonal playback state `Playing` or `Paused`; current cursor; playback accumulator; rational rate; and terminal or failure reason.
- One immutable record index retaining every outer-record ordinal, source range, command tick, optional decoded server tick, setup or state-bearing classification, and the next operation/event ordinal. Tick lookup returns exact candidate cursors and never guesses across an unindexed gap.
- Bounded complete checkpoints containing every Replay-owned setup value, entity value, ordering key, event cursor, decoder snapshot, playback cursor, and next-record position required to continue decoding against the same identities.
- An immutable `ReplaySnapshot` containing the current cursor, sign-on state, data-table state, string-table state, baselines, ordered live entities and fields, selected-game decoder state, latest command and server tick identities, and event cursor.
- An immutable `ReplayPresentationSnapshot` containing the prior and next authoritative snapshots selected for the presentation time, an exact rational interpolation fraction, per-field interpolation declarations, discontinuity flags, the ordered newly crossed event range, and the current playback state. It cannot mutate replay state.
- An ordered event log. Every game, audio, and particle event retains stable event identity, replay cursor, source ordinals, selected-game event identity, typed decoder payload, target entity when present, action identity, and coverage classification.
- A structured failure containing classification, stable code, source and decoder identities, cursor, record/message/emission ordinals, source range, tick identities, violated invariant or limit, required and available values, and the last committed snapshot identity. Failed mutation never exposes partially applied state.

## Invariants

- Replay authority advances only by applying decoded recorded operations in outer-record, inner-message, then decoder-emission order. A user command, wall-clock callback, renderer, game simulation, or inferred entity trajectory can never create replay truth.
- The command tick from the DEM record, decoded server tick, canonical tick occurrence, record ordinal, and source range remain distinct. A `ReplayCursor` is `(serverTick, occurrence, lastAppliedRecordOrdinal)` after sign-on; setup cursors retain record ordinal without inventing a server tick. Header playback counts never replace observed index boundaries.
- `Ready` requires accepted data-table, string-table, baseline, and first full entity state for the selected decoder. A delta without its named base, an entity operation before its schema and baseline, or a sign-on transition outside the decoder contract fails before mutation.
- Entity creation establishes class, baseline, generation, and initial fields atomically. A field patch targets one live generation. Deletion invalidates that generation before a later creation can reuse the entity index.
- Every decoded operation and event is applied exactly once during forward playback. Duplicate source records remain distinct by ordinal. Seek reconstruction suppresses transient event delivery, returns one discontinuity plus the target snapshot, and leaves the skipped event range queryable by cursor.
- Pause consumes no elapsed duration and emits no event. A positive rational rate scales the exact elapsed-duration accumulator; rate changes preserve the accumulated remainder. Whole authoritative tick boundaries commit before a presentation fraction is returned.
- A signed step executes only while paused, crosses at most `maxStepTicks`, lands on an indexed canonical tick boundary, returns one discontinuity, and emits no skipped transient event. An out-of-range step fails without clamping.
- Forward and backward seeks restore the nearest complete checkpoint at or before the target and replay source operations forward. An index entry without a complete checkpoint is never treated as state. Equal target cursors reached from any prior cursor produce byte-identical canonical snapshots and event cursors.
- Authoritative snapshots contain recorded values only. Interpolation receives two immutable snapshots plus decoder-declared field policy and never writes an interpolated value back into either snapshot. Creation, deletion, reset, no-interpolation markers, and seek or step discontinuities prohibit blending across that boundary.
- Audio and particle events come only from decoded recorded messages or selected-game mappings. Replay never infers an explosion, trail, sound, or stop from disappearance, distance, rendering state, or gameplay resimulation.
- Every allocation, retained byte, index entry, checkpoint, entity, field, table entry, event, operation, diagnostic, seek replay, step, rate component, and output snapshot is charged to the required limits before allocation or mutation. Limit failure is deterministic and atomic.
- Every record and decoder operation receives exactly one coverage classification. `Unsupported`, `Unknown`, `Malformed`, or `Missing` state-bearing input prevents progression beyond its source cursor; no decoder, protocol, checkpoint, or state fallback is selected.

## Ownership Exclusions

- `packages/formats/demo` owns DEM header and outer-record parsing, payload extents, command ticks, slots, packet metadata, exact source ranges, and malformed-container rejection. Replay consumes one successful immutable Demo value.
- `packages/runtime/networking` owns network-message framing and codecs, data-table and string-table wire decoding, baselines and entity-delta decoding, quantization, and shared protocol bounds. Replay owns application order and retained replay state after those codecs emit operations.
- `games/<game>` owns game decoder selection entries, class and field meaning, game events, console-command meaning, user-command meaning, and game-specific audio and particle mappings. Replay invokes the selected decoder and never embeds TF2, CS:S, or legacy-CS:GO semantics.
- `packages/runtime/simulation`, movement, physics, Entity, and game rules own gameplay advancement. Replay can expose recorded values shaped for their canonical representations but cannot invoke gameplay transitions to fill missing state.
- `packages/presentation/rendering`, `packages/presentation/particle`, and `packages/presentation/audio` consume presentation snapshots and events, interpolate or simulate presentation-only state, and own GPU and browser resources. They cannot alter Replay cursors or snapshots.
- Web applications own upload selection, browser lifecycle, controls, route state, focus, and product-specific replay experiences. Tools own inspection, capture, and inventory-generation commands. Neither may embed another replay timeline or state reconstructor.
- Demo recording, SourceTV transport, online session transport, movie encoding, replay editing, and authored camera performance tracks are outside this denominator.

## Exit Criteria

Replay is Complete only when all of these predicates pass:

- All 20 behavior rows are Ready.
- The replay-state inventory is generated, current, Accepted, and contains exactly 40 accepted items with no required item `Unsupported`, `Unknown`, `Missing`, or Blocked.
- Demo, Networking, and the TF2 recorded-state decoder dependency each has an Accepted denominator and current identity consumed by the Replay evidence.
- Controlled recordings from every accepted target profile pass open, sign-on, setup, packet, entity, field, event, tick, clock, step, seek, rewind, checkpoint, reconstruction, interpolation-input, end, error, and bound comparisons.
- Every equal cursor reached by uninterrupted playback, arbitrary seek history, or checkpoint restore has a byte-identical canonical snapshot and next transition under the same identities.
- Audio, Particle, Rendering, applications, and tools consume one current presentation snapshot and event interface; no consumer mutates replay truth or infers a missing authoritative event.
- Simulation and every gameplay behavior owner receive zero advancement calls from Replay; no duplicate timeline, state reconstructor, fallback, compatibility layer, legacy path, or stale generated inventory remains.
- Every encountered record, decoder operation, entity operation, field, event, cursor, and terminal condition has exactly one coverage classification.
