# VPK Roadmap

[`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery statuses, coverage classifications, logical paths, and Complete. [`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines denominator and evidence requirements.

## Completion Denominator

The current completion denominator contains exactly the 33 Behavior Families rows below. [`inventories/versions.md`](inventories/versions.md) contains 7 candidate version and target-layout decisions and 0 accepted items. Candidate inventory items do not enter this denominator until a checked-in generator emits the inventory and its denominator review is Accepted.

The VPK denominator is not accepted because the format-universe prerequisite is not accepted, configured TF2 lacks shared HL2/platform roots, exact CS:S and legacy Source 1 CS:GO archive indexes are Missing, and entry data-descriptor multiplicity has conflicting public evidence outside the configured TF2 indexes.

## Inputs

- One immutable directory-file source with a stable provider identity, revision, exact byte length, positioned-read operation, and cancellation signal. The source identity is either split `<base>_dir.vpk` or standalone `<name>.vpk`.
- For a split archive, one adapter that resolves only the exact segment identity `<base>_<index>.vpk` requested by the parsed index and exposes its revision, exact byte length, and positioned-read operation.
- One canonical slash-separated logical path for lookup, an optional entry-relative byte range, and operation-wide read, memory, concurrency, and queue bounds.
- An optional expected public key when the caller requires a signed archive to match a selected game/content-build trust policy.
- Valve Source SDK 2013 `src/public/vpklib/packedstore.h` at commit `88fa198fba3fb85d46d4c95018254693fdc3af0a` and Valve Developer Community `VPK (file format)` revision `496391` as the public VPK contracts.
- Exact archive indexes and directory-file bytes for one accepted content build each of TF2, CS:S, and legacy Source 1 CS:GO. Four TF2-owned families are established for configured product version `10822003`; shared TF2 dependencies, CS:S, and legacy CS:GO remain Missing.

## Outputs

- An immutable archive index containing the directory-file identity and revision; signature and version; exact section ranges; archive layout; every entry's stored extension, directory, basename, canonical logical path, CRC-32, preload range, ordered data descriptors, and total length; every archive-MD5 record; all three optional self-MD5 values; and parsed signature material.
- Exact entry lookup returning one entry, `Missing`, or a deterministic malformed-index error. Lookup never searches another archive family or provider.
- Full-entry or entry-relative range bytes assembled from preload bytes followed by the indexed data descriptors in their accepted order, with an explicit integrity result for CRC-32, archive MD5, self MD5, and signature checks that were applicable to that operation.
- A complete verification report for directory structure, directory-file self-integrity, every declared archive-MD5 range, every entry CRC-32, missing segments, and signature state.
- Deterministic `Malformed`, `Unsupported`, `Missing`, cancellation, bound, short-read, changed-source, and I/O errors containing the archive identity, operation, logical path or segment index when applicable, and no substitute bytes.

## Invariants

- All integers are unsigned little-endian values. Every addition, multiplication, conversion, section boundary, entry range, and read range is checked before allocation or I/O.
- Accepted Source 1 directory files start with `0x55AA1234` and declare version 1 or 2. Headerless archives and Source 2 VPK v3 never enter the accepted denominator.
- A version 1 directory file is `12-byte header | tree | directory-contained data`. A version 2 directory file is `28-byte header | tree | file-data section | archive-MD5 section | other-MD5 section | signature section`.
- The tree is consumed within exactly `TreeSize` bytes. Its extension, directory, and basename lists each end with an empty C string; the final empty extension ends the tree; no unconsumed tree byte is permitted.
- A single-space component means an absent extension, root directory, or absent basename. Every other component is non-empty ASCII. Reconstructed paths contain `/`, no absolute prefix, no empty, `.` or `..` component, no backslash, no NUL, and no ASCII control character.
- The index preserves stored component spelling and exposes one ASCII-lowercased canonical logical identity. Two entries with the same canonical identity make the complete index `Malformed`; no first-wins or last-wins result exists.
- Preload bytes immediately follow their entry metadata inside the tree. Entry data is uncompressed and equals preload bytes followed by its accepted ordered data ranges. A zero-length range is valid; an empty entry has zero preload bytes and zero data bytes.
- Archive index `0x7fff` addresses the directory-file data section. Every other accepted archive index addresses only the exact segment derived from the archive family identity.
- Split segments contain raw addressable bytes and have no VPK header. Segment indexes need not be contiguous, and unreferenced bytes or gaps are not entries and do not make an archive malformed.
- CRC-32 uses CRC-32/ISO-HDLC over the complete assembled entry: reflected polynomial `0xEDB88320`, initial value `0xffffffff`, and final XOR `0xffffffff`.
- A range read never reports entry CRC-32 as verified unless the complete entry has been examined. It reports every integrity mechanism as `Not present`, `Not evaluated`, `Verified`, or `Invalid` without promoting one mechanism to another.
- Archive-MD5 records are 28 bytes each and cover the exact declared segment index, offset, and length. The other-MD5 section is absent at length 0 or contains exactly the 16-byte tree MD5, 16-byte archive-MD5-section MD5, and 16-byte whole-file MD5 at length 48.
- The whole-file MD5 covers directory-file bytes from offset 0 through the byte immediately before the stored whole-file MD5. It excludes that digest and the signature section.
- A non-empty signature section contains exactly a little-endian public-key length, public-key bytes, little-endian signature length, and signature bytes. RSA PKCS#1 v1.5 with SHA-256 verifies all directory-file bytes preceding the signature section.
- Parsing, lookup, and reads never extract an archive, recursively scan a directory, infer an installation, inspect an unreferenced segment, or continue to another provider after an indexed failure.
- The index is immutable. Concurrent reads use positioned I/O and produce the same bytes, integrity states, and errors as the same reads in serial order; no shared file cursor affects a result.
- Cancellation returns no partial success, publishes no verified state from unfinished work, and releases operation-owned buffers and source handles.

## Ownership Exclusions

- `packages/content` owns provider registration, path-ID eligibility, provider precedence, cache selection, first-provider choice, and archive-family selection. VPK owns the selected family's structure and exact indexed reads.
- `games/tf2`, `games/css`, and `games/csgo` own content-build-specific archive-family membership, expected signing keys, and policies that require or permit unsigned archives. VPK parses and verifies supplied archive and key bytes without choosing game policy.
- Concrete filesystem, browser, HTTP, and object-store adapters own positioned byte I/O. VPK owns the requested offsets, lengths, ordering, cancellation propagation, integrity checks, and errors.
- `packages/formats/bsp` owns BSP embedded PAK ZIP data. A BSP PAK is not a VPK segment or fallback source.
- The leaf owner assigned by `packages/formats/inventories/formats.md` parses each resource returned from an entry read; VPK never interprets entry payload bytes.
- `tools/playsrc` owns command orchestration, local configuration loading, listing, verification, and extraction workflows. Filesystem extraction-path creation is not part of the VPK package interface.
- `packages/asset-store` owns playsrc-compiled objects, manifests, catalogs, channels, and publication. VPK returns Source bytes and never stores compiled output.
- VPK creation, mutation, incremental packing, and signing are not declared operations in the current project denominator. Activating one requires adding its complete encoding behavior family to this roadmap before implementation.

## Exit Criteria

The VPK package is Complete only when all of these predicates pass:

- All 33 Behavior Families rows are Ready.
- The format-universe prerequisite and this leaf denominator have Accepted review records for the same VPK identity.
- The version/layout inventory is emitted by one checked-in command, contains exactly the accepted item set, and includes exact TF2, CS:S, and legacy Source 1 CS:GO content-build archive indexes.
- Fixed vectors cover versions 1 and 2; standalone and split archives; every section-presence profile in the accepted inventory; root, extensionless, preload-only, directory-contained, segmented, empty, duplicate, missing, truncated, corrupt, unsigned, signed, and wrong-key cases.
- Full-entry bytes and listings match Valve `vpk` output, CRC/MD5 verification matches `vpk checkhash`, and signature results match `vpk checksig` for the same fixed archives.
- Content provider integration resolves a VPK winner through the immutable index and exact reader without duplicate parsing, archive extraction, provider-order logic, fallback, or an alternate integrity path.
- Concurrent and cancelled reads satisfy the accepted queue, concurrency, byte, and memory bounds on browser and native adapters.
- No required entry, version, section profile, archive family, producer, consumer, or behavior remains Unsupported, Unknown, Missing, Partial, or Blocked.

- **Format-universe prerequisite:** `packages/formats/ROADMAP.md` records its 62-item candidate as Not accepted and the VPK inventory cannot select its final version set. Checked that roadmap, `packages/formats/inventories/formats.md`, and the root Owner Registry.
- **Target content builds:** `playsrc.local.json` is Missing and the local configuration contract names no CS:S or legacy CS:GO root. Exact archive indexes, directory-file hashes, section profiles, and segment sets are unavailable. Checked `playsrc.local.example.json`, Source SDK `game/mod_tf/gameinfo.txt`, public TF2 depot 441 manifest `1804278129270892792`, public CS:S depot 241 manifest `6941588918651947824`, and public legacy CS:GO depot 731 records; none selects all three playsrc target builds.
- **Entry descriptor multiplicity:** Valve Developer Community `VPK (file format)` revision `496391` specifies one archive descriptor followed by `0xffff`; its public talk page reports repeated descriptor triples for fragmented entries; Source SDK `VPKContentFileInfo_t` exposes one chunk; no selected target archive index resolves whether multiple descriptors enter the denominator.
- **Execution bounds:** exact browser and native maxima for directory bytes, tree bytes, entries, path bytes, cumulative preload, descriptors, segments, integrity records, key/signature bytes, queued reads, concurrent reads, one read, and in-flight memory are undecided. Source SDK `packedstore.h` establishes a 200 MiB default writer chunk and 512 cached archive handles, but those implementation constants do not establish playsrc limits.
- **Inventory generator:** no checked-in command generates `packages/formats/vpk/inventories/versions.md`; its 7 candidate items therefore contribute 0 accepted denominator items.
