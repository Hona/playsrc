# PHY Roadmap

Authored polygon hierarchy decoding retains every 28-byte node, child relationship, bound, optional enclosing hull, subtree link, and 16-byte convex header. Terminal pieces reference one shared geometry array. Configured sticky, locker, and `jump_beef` inputs preserve **127 surfaces, 829 nodes, 478 terminal pieces, 484 geometries, and six enclosing hulls**. Signed point-array offsets, raw reserved bytes, cycles, invalid links/extents, and node/hull limits have targeted tests. This extends existing geometry representation rows; it does not accept the full format denominator or add new rows.

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery status, coverage classification, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 20 behavior rows. [`inventories/versions-and-sections.md`](inventories/versions-and-sections.md) contains 33 candidate profile, section, keydata-block, and model-association decisions and 0 accepted items. The current completion denominator is therefore 20 behavior rows. Acceptance of all 33 candidate items without a roadmap change would make the denominator 53 items.

The denominator covers bounded parsing, lossless serialization, and runtime-neutral representation of little-endian Source 1 model `.phy` files and the same length-prefixed collision payload when a BSP parser supplies collision bytes, keydata bytes, and a solid count separately. It covers headers, checksums, ordered solids, collision encodings, convex geometry, triangle metadata, physical parameters, PHY keydata, ragdoll metadata, and model associations required by Team Fortress 2, Counter-Strike: Source, and legacy Source 1 Counter-Strike: Global Offensive. Source 2, byte-swapped console assets, simulation, collision queries, and game behavior are excluded.

The denominator is Not accepted. The prerequisite format inventory is Candidate, the child inventory has no generator or review record, exact declared-game content indexes are Missing, and several serialized profiles remain unresolved.

## Inputs

- Either one immutable `.phy` byte sequence resolved at an exact Source logical path, with content build, provider identity, source location, and SHA-256 hash; or one caller-supplied collision payload containing exact collision bytes, exact keydata bytes, the declared solid count, source identity, and provenance. The second form does not include BSP model-block framing.
- One explicit accepted profile from [`inventories/versions-and-sections.md`](inventories/versions-and-sections.md). The parser never selects a profile from payload plausibility or retries another profile after failure.
- An optional model association containing the exact companion `.mdl` logical path, signed 32-bit MDL checksum, and ordered skeleton bone identities. A caller claiming a PHY/MDL association must supply this input.
- A required limits record containing `maxInputBytes`, `maxRetainedBytes`, `maxSolids`, `maxSolidBytes`, `maxKeydataBytes`, `maxTreeNodes`, `maxTreeDepth`, `maxConvexPieces`, `maxTriangles`, `maxPoints`, `maxKeydataTokens`, `maxKeydataTokenBytes`, `maxKeydataDepth`, and `maxDiagnostics`. Every field is a non-negative integer and no operation has an unbounded mode.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/phyfile.h`, `vcollide.h`, `vcollide_parse.h`, `vphysics_interface.h`, `vphysics/constraints.h`, `filesystem_helpers.*`, and `bspfile.h`; `src/common/studiobyteswap.cpp`; `src/utils/glview/glview.cpp`, `vbsp/ivp.cpp`, and `vrad/vradstaticprops.cpp`; and the PHY keydata consumers in `src/game/shared/physics_shared.cpp`, `ragdoll_shared.cpp`, and `props_shared.cpp`.
- Valve Developer Community `PHY` revision `462589` as the public collision-section and text-section contract.
- Exact archive indexes and source bytes for one accepted content build each of TF2, CS:S, and legacy Source 1 CS:GO. TF2 build `10822003` is configured and supplies exact indexed inputs. The CS:S and legacy Source 1 CS:GO builds are Missing.

## Outputs

- An immutable PHY asset retaining every exact supplied byte extent, source identity, selected profile, and provenance. A standalone result also retains its 16-byte file header, signed 32-bit header fields, and model-association result; a separately supplied payload has no invented file header.
- An ordered solid list retaining each signed 32-bit length prefix, encoded range, exact body bytes, discriminator, version, model type, section ranges, coverage classification, and diagnostic set.
- For each decoded polygon solid, exact encoded scalar bits plus runtime-neutral Source-space center of mass, rotation inertia, upper-limit radius, drag-axis areas, surface-deviation value, axis-map bytes, rooted convex partition, ordered convex pieces, points, triangles, per-convex game data, per-triangle seven-bit material index, virtual flag, and unclassified bits.
- A lossless PHY keydata syntax document retaining exact byte spans, whitespace, comments, quoted or unquoted token form, token bytes, block order, repeated keys, nesting, terminating NUL bytes, and suffix bytes; plus typed views for accepted section identities without changing the syntax document.
- Association diagnostics for checksum mismatch, same-stem mismatch, absent or duplicate solid indexes, out-of-range solid references, unresolved parent or bone names, and constraint reference errors. Association diagnostics do not rewrite encoded identities.
- A structured error naming source identity, profile, operation, byte range, solid or section identity, declared value, limit value, and exactly one `Malformed`, `Unsupported`, `Unknown`, or `Missing` classification.

## Invariants

- All accepted binary numeric fields are little-endian. Every binary integer and binary32 field retains its exact encoded bits; derived numeric values never replace source bits.
- The accepted standalone file profile begins with exactly four signed 32-bit fields and has `size == 16` and `solidCount > 0`. `id` and `checkSum` remain observable even when their values are not interpreted.
- The selected profile determines accepted identifiers, versions, model types, and section layouts. Payload bytes never cause branch guessing, fallback parsing, or profile widening.
- Exactly `solidCount` solids are consumed in source order. Each solid begins with a signed 32-bit body length. Negative lengths, checked-addition overflow, a body outside the supplied bytes, and fewer than the declared count are Malformed.
- After the final solid, all remaining standalone bytes are keydata. For a separately supplied payload, collision bytes must end after the final solid and keydata bytes are a separate exact extent.
- A modern polygon body begins with a 28-byte `VPHY` metadata section containing version `0x0100`, model type `0`, collision-surface byte length, three drag-axis-area binary32 values, and axis-map byte length. Checked section lengths must consume the complete body.
- A legacy polygon body begins directly with its compact collision surface. Legacy discriminator acceptance is profile-controlled; an unknown or byte-swapped discriminator is retained and classified rather than decoded as polygon geometry.
- A compact polygon surface begins with 48 bytes of metadata. Its declared byte length, root offset, center of mass, rotation inertia, upper-limit radius, surface-deviation value, reserved words, and discriminator remain observable.
- Convex partition nodes are 28-byte records. The root is relative to the compact-surface start; a non-terminal right-child offset and a terminal convex-piece offset are relative to their node. Every reached node must be in range, acyclic, and within the caller's count and depth limits.
- Each convex piece has a 16-byte header followed by its declared 16-byte triangle records. Its point-table offset is relative to the convex-piece start. Triangle point references address 16-byte point records. Shared ranges remain shared; repeated references do not create invented source records.
- Persisted positions and distances use meters and the collision payload axis order. A persisted position `(a, b, c)` derives Source-space inches `(a / 0.0254, c / 0.0254, -b / 0.0254)`, and a persisted distance `r` derives `r / 0.0254` Source inches. Typed face order must produce the same ordered Source-space triangle vertices as `ICollisionQuery`; serialization retains the encoded edge order.
- Every convex piece retains all 32 game-data bits. Every triangle retains all 16 encoded bytes, its three point references, seven-bit material index, virtual flag, and every unclassified bit. Unknown bits never become a material, contents mask, or game rule.
- Non-finite geometry, an out-of-range point reference, a cyclic partition, an impossible record extent, or count arithmetic overflow is Malformed. Degenerate but finite triangles remain represented and receive the classification selected by the accepted profile.
- The keydata extent contains a NUL terminator; absence is Malformed. The first NUL ends the document. All terminator and suffix bytes remain in output. An accepted profile decides whether additional NUL padding is valid; nonzero suffix bytes are never ignored.
- PHY keydata tokenization recognizes Source byte whitespace, `//` and `/* */` comments, quoted and unquoted tokens, and the single-character tokens `{`, `}`, `(`, `)`, `'`, and `:`; blocks are brace-delimited. It performs no escape substitution. Exact token bytes and spelling survive ASCII-insensitive section and field lookup.
- Known typed sections never discard an unknown key or nested child. Unknown section names and unknown modern or legacy collision sections retain exact ranges and receive one coverage classification.
- Solid, constraint, and bone references are encoded identities. Structural parsing retains every value; association validation reports invalid or unresolved references without renumbering, reparenting, or synthesizing a solid.
- Parsing, typed projection, association validation, and serialization check every range, count, recursion step, token, retained byte, and allocation against the required limits before allocation or traversal.
- A parser error returns no partially authoritative PHY asset. Diagnostic context may retain validated identities and ranges but cannot be consumed as collision or physics data.
- Serializing an unmodified successful parse emits bytes identical to the supplied standalone file or to the supplied collision/keydata payload pair.

## Ownership Exclusions

- Provider ordering, exact logical-path resolution, content-build selection, and retrieval of `.phy`, `.mdl`, or `.bsp` bytes belong to `packages/content`.
- BSP lump 29 model headers, model indexes, collision/keydata extents, terminator records, and base-map association belong to `packages/formats/bsp`. PHY owns only the supplied length-prefixed solid stream and PHY keydata payload.
- MDL/VVD/VTX/ANI parsing, skeleton construction, model flags, and selection of a same-stem PHY companion belong to `packages/formats/studio-model`. PHY validates the supplied companion checksum and encoded solid/bone references.
- Canonical collision-shape construction, acceleration structures, contents assignment, ray traces, hull sweeps, overlaps, and contact queries belong to `packages/world/collision`.
- Rigid-body creation, mass/inertia application, surface-property resolution, material response, damping, drag, constraints, ragdoll advancement, sleeping, contacts, and solver behavior belong to `packages/runtime/physics`.
- Surface-property audio, particle, decal, and rendering effects belong to `packages/presentation/audio`, `packages/presentation/particle`, and `packages/presentation/rendering` respectively.
- Break/spawn effects, prop classes, collision groups, damage, contents policy, ragdoll policy, and other game-specific interpretations of PHY keydata belong to `games/tf2`, `games/css`, or `games/csgo`.
- Player movement belongs to `packages/runtime/movement`; gameplay coordination belongs to `packages/runtime/simulation`.
- PHY creation, mutation, canonical rewriting, model compilation, and inventory generation belong to `tools/*`; immutable compiled artifacts belong to `packages/asset-store`.

## Exit Criteria

The PHY package is Complete only when all of these predicates pass:

- All 20 behavior rows are Ready.
- The Source format universe and this PHY denominator have Accepted review records for the same PHY identity.
- The version-and-section inventory is generated, current, Accepted, includes exact TF2, CS:S, and legacy Source 1 CS:GO content builds, and contains no Blocked item.
- Every accepted header, checksum relation, solid count, solid encoding, collision section, convex piece, triangle, point, physical parameter, game-data value, keydata section, constraint, ragdoll record, unknown value, malformed range, truncation, overflow, and allocation boundary satisfies its evidence predicate.
- Every successful standalone parse and separately supplied payload parse re-emits bytes identical to its input and retains provenance and content hashes.
- Every named producer and consumer uses the current PHY interface, and no duplicate reader, fallback shape, compatibility layer, legacy path, parser-owned simulation behavior, or stale inventory remains.
- PHY has no dependency on world, runtime, presentation, game, application, service, or renderer packages.

## Blockers

- **Format-universe prerequisite:** [`../ROADMAP.md`](../ROADMAP.md) and [`../inventories/formats.md`](../inventories/formats.md) remain Candidate and Not accepted. PHY cannot accept its child denominator before the parent review assigns the current identity.
- **Inventory generator and content builds:** no checked-in command emits [`inventories/versions-and-sections.md`](inventories/versions-and-sections.md), and no exact archive/index input exists for CS:S or legacy Source 1 CS:GO. TF2 build `10822003` is configured, but no checked generator enumerates its complete PHY/model/BSP universe. Cross-game profile, discriminator, section, keydata-block, ID, padding, and model-association occurrence is therefore Missing.
- **Non-polygon profiles:** public contracts identify modern model types and legacy MOPP/compact discriminators incompletely, and no declared-build bytes establish required MOPP, ball, virtual, zero-tag legacy, or other collision bodies. Checked the named SDK headers, byte-swap utility, public PHY revision, and the absent content indexes.
- **Axis-map section:** the modern header declares an axis-map byte length, but the checked public contract does not define non-empty entries or accepted target-game occurrence. The parser must preserve exact bytes; typed interpretation remains Blocked.
- **Custom keydata universe:** public consumers establish `solid`, `staticsolid`, `fluid`, `materialtable`, `virtualterrain`, `ragdollconstraint`, `collisionrules`, `animatedfriction`, `break`, and TF2 `spawn`; public PHY documentation also identifies `editparams`. Exact fields and occurrence for every declared-game custom block remain Missing without the three content-build inventories.
- **BSP payload ownership conflict:** `packages/formats/bsp/ROADMAP.md` assigns VPhysics payload decoding to `packages/runtime/physics`, while this assignment and the root PHY leaf assign bounded collision-payload parsing to `packages/formats/phy`. Resolve the roadmaps so BSP owns only `dphysmodel_t` framing, PHY owns supplied solid/keydata payload parsing, world collision owns query structures, and runtime physics owns simulation.
