# StudioModel Roadmap

[`../../../docs/roadmap-contract.md`](../../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../../TERMINOLOGY.md`](../../../TERMINOLOGY.md) defines delivery status, coverage classification, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 42 behavior rows. The candidate inventories contain 90 decisions: 8 file/version profiles and 82 serialized record families. They contribute 0 denominator items until checked-in generators emit them and a denominator review accepts them. The current completion denominator therefore contains 42 items and is Not accepted. Acceptance of all 90 current candidate inventory items would make the denominator 132 items.

The target is the little-endian PC StudioModel family assigned by the parent format inventory for Team Fortress 2, Counter-Strike: Source, and legacy Source 1 Counter-Strike: Global Offensive: `IDST` MDL, `IDAG` ANI, `IDSV` VVD version 4, VTX version 7, and VHV version 2. The MDL candidate set is versions 44, 45, 46, 47, and 48. Exact declared-game occurrence remains Missing. Console byte order, console VTX profiles, Source 2 models, PHY payload decoding, model-source formats, GPU resources, and animation-state decisions are excluded.

## Inputs

- A `StudioModelLoadRequest` containing one exact `.mdl` Source logical path, one explicit profile from [`inventories/versions.md`](inventories/versions.md), one explicit VTX identity from `.vtx`, `.dx80.vtx`, `.dx90.vtx`, or `.sw.vtx`, and the root bytes with provenance and SHA-256 hash.
- A dependency callback that receives the requesting logical identity, role, and exact requested logical path, then returns immutable bytes with provenance and content hash or `Missing`. The package never selects a provider, searches a directory, probes another extension after failure, or discovers content.
- Optional VHV bytes supplied through a separate request containing the exact map-owned logical identity and the expected MDL checksum. VHV identity is not derived from the MDL basename.
- A required limits record containing `maxFileBytes`, `maxAggregateInputBytes`, `maxDependencyCount`, `maxIncludeDepth`, `maxIncludedModels`, `maxRecords`, `maxStrings`, `maxStringBytes`, `maxVertices`, `maxIndices`, `maxAnimationFrames`, `maxDecodedAnimationSamples`, `maxOpaqueBytes`, `maxOwnedBytes`, and `maxDiagnostics`. The package defines no unbounded mode.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a`: `src/public/studio.h`, `optimize.h`, `studio.cpp`, `studio_generic_io.cpp`, `studio_virtualmodel.cpp`, `bone_setup.{h,cpp}`, `src/public/materialsystem/hardwareverts.h`, `src/common/studiobyteswap.{h,cpp}`, `src/utils/motionmapper/motionmapper.h`, and StudioModel consumers under `src/utils/vbsp` and `src/utils/vrad`.
- Public Valve Developer Community MDL, ANI revision `428841`, VVD, VTX, VHV, and Studio model contracts. Revisions other than the ANI revision are `Unknown` until retained immutable snapshots are recorded.
- Exact archive indexes for one declared TF2, CS:S, and legacy Source 1 CS:GO content build. These inputs are Missing.

## Outputs

- An immutable `StudioModelDocument` containing the selected profile; root identity; ordered source-file identities, provenance, hashes, versions, checksums, and byte lengths; exact dependency trace; model header metadata; raw unknown fields; and every typed item in [`inventories/record-families.md`](inventories/record-families.md).
- A runtime-neutral skeleton containing ordered bones, parent indexes, base transforms, pose-to-bone transforms, flags, procedural-bone parameters, linear-bone arrays, source-bone transforms, controllers, hitbox records, and bone-driven flex metadata.
- Ordered animation and sequence data containing descriptors, block and section references, exact encoded track records, decoded integer-frame local transforms, movements, IK metadata, local hierarchies, events, autolayers, pose keys, sequence weights, transition records, and embedded KeyValues byte ranges. It contains no selected sequence, current cycle, blended pose, entity state, or event effect.
- Ordered material, skin, bodypart, model, mesh, LOD, vertex, tangent, topology, attachment, eyeball, mouth, and flex metadata. Geometry identities are `(bodypart, model, lod, mesh, stripGroup, primitive)` and vertices retain both VVD source identity and VTX mesh-local identity.
- A composed include-model view containing dependency order and local-to-root remap tables for bones, sequences, animations, attachments, pose parameters, nodes, and autoplay IK locks, while retaining each source document independently.
- A VHV document containing its exact source identity, version, checksum, `VERTEX_COLOR` format, four-byte stride, declared vertex count, ordered mesh ranges, exact BGRA8 records, and alignment ranges.
- A `StudioModelDependencyTrace` recording every exact companion and include request, result, provenance, checksum decision, cycle decision, and limit decision in request order.
- One structured diagnostic containing coverage classification, stable error code, source identity, byte range, record-family identity, index stack, dependency chain, offending value, and required bound.

## Invariants

- Parsing is pure over supplied bytes and dependency responses. It performs no filesystem, archive, cache, network, rendering, game, or platform discovery operation.
- The selected version profile is mandatory. Signature, version, extension role, and little-endian field contract must match it; no profile is inferred from record size, path, checksum, another companion, or a failed parser.
- MDL, ANI, VVD, VTX, and VHV declared file lengths, table ranges, relative offsets, strings, and child records are validated with widened checked arithmetic before access or allocation.
- MDL is the checksum authority. VVD, VTX, and supplied VHV checksums equal the MDL checksum. A PHY dependency retains the expected MDL checksum for validation by `packages/formats/phy`.
- An MDL with one or more bodyparts requires the selected VVD and VTX companions. An MDL with no bodyparts produces a valid metadata/animation document without invented geometry companions.
- ANI is requested exactly when an animation descriptor or section references a nonzero external block. Block 0 remains MDL-local; external block indexes begin at 1. A required missing ANI produces `Missing`, never an inline-data fallback.
- Every include model is resolved by its exact stored logical identity. Include cycles, duplicate dependencies, missing includes, and depth/count exhaustion are reported deterministically; none are replaced by root-local records.
- Source order is retained for every table. Duplicate names and records remain distinct unless the declared include-composition contract produces a separate remap view; source documents are never mutated by composition.
- Raw string bytes, original separators, termination, and source range are retained. Derived Source logical paths are slash-separated and reject empty, `.` and `..` components without rewriting the stored bytes.
- The hard format ceilings are 128 bones, 4 bone controllers, 8 LODs, 3 bone influences per vertex, 32 texture/material references, 1,024 flex descriptors, 96 flex controllers, 24 pose parameters, and 256 animation blocks. A lower caller limit takes precedence.
- VVD fixups produce exactly the declared vertex count for each retained root LOD. VTX bodypart, model, LOD, and mesh cardinalities match the corresponding MDL hierarchy before geometry assembly.
- VTX indices are strip-group-local, VTX vertices identify MDL mesh-local vertices, MDL mesh/model offsets identify VVD vertices, and VVD fixups select the source vertex for one LOD. These identities remain distinct in output.
- Triangle-list and triangle-strip topology is represented exactly as encoded. A derived triangle list is additional output and never replaces source strips, degenerate indexes, strip flags, or bone-state changes.
- Flex deltas retain fixed-point or binary16 source encoding, scale, target thresholds, pair, vertex-animation type, and affected mesh-local vertex. Wrinkle data is never invented for a normal flex.
- Accepted VHV v2 uses `VERTEX_COLOR`, a four-byte vertex stride, BGRA byte order, and 512-byte-aligned vertex-data start and file extent. Mesh vertex counts sum to the header total and every mesh range lies inside the aligned payload.
- Unknown flags, opcodes, procedural-bone types, record variants, reserved words, padding, and unconsumed tails are preserved with exact bytes and a coverage classification. An unknown value never selects another layout.
- Every count, product, sum, recursion step, dependency byte, decoded sample, opaque record, retained source byte, and diagnostic is charged to the required limits before allocation.
- A failed load emits diagnostics and dependency trace but no partially authoritative `StudioModelDocument`.

## Ownership Exclusions

- Exact logical-path canonicalization, provider ordering, VPK/directory lookup, byte retrieval, caching, and provenance acquisition belong to `packages/content`.
- QC/QCI, SMD/VTA, model-schema DMX, model compilation, and command orchestration belong to the proposed `packages/formats/model-source` owner and `tools/*`.
- PHY header and payload parsing, collision shapes, constraints, mass interpretation, and physics simulation belong to `packages/formats/phy`, `packages/world/collision`, and `packages/runtime/physics`. StudioModel retains only MDL collision references and expected checksum.
- VMT parsing belongs to `packages/formats/vmt`; material candidate resolution and surface-property meaning belong to `packages/world/material`; texture decoding belongs to `packages/formats/vtf`.
- Embedded MDL and sequence KeyValues syntax parsing belongs to `packages/formats/keyvalues`. StudioModel owns the containing byte range and record association.
- Static-prop instance identity and association of a map VHV logical path with a model instance belong to `packages/formats/bsp` and `packages/world/map`.
- Hitbox selection, collision queries, contents meaning, and gameplay damage rules belong to `packages/world/collision` and `games/<game>`.
- Activity mapping, sequence selection, bodygroup/skin choice, animation cycle, playback rate, event effects, entity pose state, prediction, and TF2-, CS:S-, or legacy CS:GO-specific model behavior belong to `games/<game>`, `packages/runtime/replay`, and the gameplay authority.
- Sequence blending, pose interpolation, procedural-bone evaluation, IK solving, flex-controller values, flex-rule application, and presentation-only pose state belong to `packages/presentation/rendering`. StudioModel owns only decoded records and deterministic integer-frame local animation samples.
- GPU buffers, materials, shaders, VTX hardware-profile selection for a device, VHV lighting use, LOD selection by camera, skinning, culling, scene nodes, and pixels belong to `packages/presentation/rendering`.
- Audio or particle effects referenced by animation events belong to `packages/presentation/audio` and `packages/presentation/particle`; game-owned event meaning remains in `games/<game>`.
- Content-addressed compiled artifacts, manifests, and publication state belong to `packages/asset-store`.
