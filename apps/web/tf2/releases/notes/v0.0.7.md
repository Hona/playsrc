# playsrc v0.0.7

This update turns the browser port from a two-map Soldier/Demoman inspection build into a much more complete local Team Fortress 2 game. 2Fort arrives with playable Capture the Flag, all nine classes can join RED or BLU, authored team and class menus are available, bots can navigate and fight, and multiple classes now carry their real stock weapons.

The release also rebuilds Source water rendering, restores the actual TF2 crosshair and class portraits, fixes mouse-look and movement presentation, corrects decal and HUD depth ordering, and publishes one shared three-map content closure for `jump_beef`, `pl_upward`, and `ctf_2fort`.

## World and Maps

### 2Fort Arrives

`ctf_2fort` is now a declared browser map alongside `jump_beef` and `pl_upward`.

The original Source BSP is loaded with its authored world surfaces, visibility, collision, lightmaps, water, map photograph, and 2,265 static props. Its BSP contains 22,751,863 bytes and is verified against SHA-256 `cbd191411c0be57099da73458167001ec80d58bf37c71cb3c36b2911b6e80fd7`.

Map selection, loading labels, resource graphs, dependency ledgers, and the shared catalog now recognize all three configured maps. Changing maps replaces the active world without retaining another map's particles, UI state, or camera visibility.

Related pull requests: [#58](https://github.com/Hona/playsrc/pull/58), [#36](https://github.com/Hona/playsrc/pull/36), and [#48](https://github.com/Hona/playsrc/pull/48).

### Capture the Flag

2Fort now runs its actual RED-versus-BLU Capture the Flag rules rather than existing solely as a visual map.

- Both intelligence cases retain their team ownership, world identity, pickup eligibility, carried state, and visible status.
- Dropped intelligence follows its authored return timer and resets correctly.
- Capturing an enemy briefcase requires the correct capture area and updates the round score.
- Captures trigger the correct notifications, announcer behavior, critical-bonus state, and round-victory presentation.
- Bot objective hooks expose intelligence pickup, delivery, and return decisions to the local game.

Related pull request: [#67](https://github.com/Hona/playsrc/pull/67).

### Upward World and Track Movement

`pl_upward` retains its full authored Source map, including 558 displacement patches, 1,244 static props, and its separate 3D sky.

The prop set remains split into 1,184 main-world props and 60 sky-owned props, with 234 distinct model identities, 554 physics-solid prop occurrences, and 2,480 indexed static-lighting objects.

Source `path_track` and `func_tracktrain` movement now preserve authored routing, acceleration, orientation, and collision. These foundations are available for map entities and future Payload behavior, but the map's complete physics-driven cart and breakable constraint are not yet available.

Related pull requests: [#31](https://github.com/Hona/playsrc/pull/31) and [#70](https://github.com/Hona/playsrc/pull/70).

## Classes and Joining

### All Nine TF2 Classes

Scout, Soldier, Pyro, Demoman, Heavy, Engineer, Medic, Sniper, and Spy now have their canonical TF2 class identities and authored foundational player state.

Class selection preserves the correct base health, movement speed, eye height, collision hull, team identity, and spawn behavior. Scout also retains its Source double jump. Existing Soldier and Demoman behavior remains intact when selecting or changing another class.

Related pull request: [#49](https://github.com/Hona/playsrc/pull/49).

### Authentic Team Selection

Joining a local game now follows TF2's real team-admission flow instead of silently starting on an invented team.

The team menu includes RED and BLU choices, authored animated doors, spectator presentation, current team rosters, balancing rules, auto-assignment, accessible controls, and explicit unassigned or spectator player states.

Choosing a team proceeds into the existing class-selection flow. Team changes, spectator transitions, menu focus, and unavailable choices preserve the actual game-owned rules rather than merely changing DOM visibility.

Related pull request: [#59](https://github.com/Hona/playsrc/pull/59).

### Authentic Class Selection

The class menu displays all nine playable classes using the configured TF2 VGUI resources, authored RED/BLU portraits, class tips, keyboard selection, mouse selection, and real 3D model panels.

Initial joins, later class changes, random-class selection, and the active in-game HUD all use the same authoritative class state.

Related pull request: [#51](https://github.com/Hona/playsrc/pull/51).

### Demoman

### Projectile Effects and Fire-Tick Attachments

Projectile particles now advance through atomic generation-owned transactions. Ordinary trail termination stops new emission without deleting particles that should still finish naturally, and invalid or reversed transactions cannot partially mutate particle state.

Launcher, muzzle, and backblast transforms are retained for each authoritative fire tick. Coalesced gameplay publications no longer attach multiple shots to the final frame's incorrect viewmodel pose.

Related pull requests: [#30](https://github.com/Hona/playsrc/pull/30) and [#44](https://github.com/Hona/playsrc/pull/44).

- The Multiplayer options panel and `cl_crosshair_red`, `cl_crosshair_green`, `cl_crosshair_blue`, `cl_crosshair_scale`, and `cl_crosshair_file` all control one live crosshair state.
- Color, size, centering, pause visibility, class changes, and map replacement follow the game-owned rules.

Related pull request: [#34](https://github.com/Hona/playsrc/pull/34).

### Class Portraits

All 18 authored RED and BLU class portraits are available in the lower-left HUD. The inexpensive 2D path uses the original configured image directly, while the existing 2D-versus-3D preference remains available.

### Correct Ammo Shadows and Window Ordering

Source VGUI sibling ordering now keeps authored dark ammo shadows behind their bright foreground text, including equal-depth labels that previously rendered in the wrong order.

The configured foreground remains `[235,226,202,255]`, the opaque shadow remains `[46,43,42,255]`, and the translucent reserve shadow retains its original alpha. Independent console, Options, popup, and modal windows now resolve real visual stacking and input hit testing correctly.

### Main Menu, Escape, and Loading

Unsupported promotional or account-only controls no longer appear when the required source data is absent. The main menu and loading screens use their configured presentation, show the actual map name and game mode, and display authored map photographs when one exists.

Pressing Escape during gameplay opens the pause menu; pressing it again resumes gameplay and restores Pointer Lock only after the game-owned transition completes. Failed loads, repeated map changes, and startup errors recover through valid GameUI state instead of returning `action-unavailable`.

Related pull requests: [#28](https://github.com/Hona/playsrc/pull/28), [#36](https://github.com/Hona/playsrc/pull/36), and [#48](https://github.com/Hona/playsrc/pull/48).

## Rendering and Water

### Authored Source Water

Water surfaces now use their original Source material behavior instead of a translucent diagnostic-colored plane.

The renderer preserves authored reflection and refraction targets, animated normal maps, Fresnel response, clipping planes, water fog, underwater blur, surface intersection, depth writes, and separate above-water or underwater views.

Fixed headed `jump_beef` measurements retained these frame-time results:

- Above water: 2.1 ms median, 4.1 ms 95th percentile.
- Underwater: 1.5 ms median, 2.7 ms 95th percentile.
- Repeated water entry and exit: 2.2 ms median, 5.1 ms 95th percentile.
- Surface intersection: 3.3 ms median, 4.4 ms 95th percentile.

All four scenarios remain below the 8.33 ms frame target without removing reflections, depth, effects, or authored texture data.

Related pull request: [#37](https://github.com/Hona/playsrc/pull/37).

### Animated Upward Materials

`pl_upward` now retains its actual animated `LightmappedGeneric` water material instead of incorrectly treating every water-like surface as the generic Water shader.

All 30 authored normal-map frames, cubemap contribution, original texture transforms, and proxy timing reach the renderer. Shared immutable VTF inspection removes 1,496 repeated texture-metadata parses while preserving every authored frame and mip.

Related pull request: [#50](https://github.com/Hona/playsrc/pull/50).

### Water Movement and Rocket Jumping

Fluid contents now come from dedicated Source point-content queries rather than a stationary collision-trace approximation. Water, slime, overlapping volumes, and the separately retained TF2 in-water flag remain distinct through gameplay, WASM, and browser snapshots.

Underwater airborne crouch rocket jumps no longer receive the incorrect oversized force: the fixed scenario changes from approximately 1,000 impulse and 940 next-tick speed to the authored 900 impulse and 846 next-tick speed.

A real headed water-brush capture also observed 86 self damage, 391.6 units per second of upward velocity, 257,834 changed visible pixels, and 66.98 simulation ticks per second.

Related pull requests: [#32](https://github.com/Hona/playsrc/pull/32) and [#42](https://github.com/Hona/playsrc/pull/42).

### Wall Decals Stay Behind Walls

Painted jump numbers and other Source decals no longer appear through nearer opaque geometry.

The corrected WebGPU depth bias preserves the authored decal receiver and normal wall depth. The fixed headed scenario reduced incorrectly visible `14` pixels from 2,140 to zero while retaining 2,127 unobstructed distant pixels and 32,619 nearby visible pixels.

Related pull request: [#29](https://github.com/Hona/playsrc/pull/29).

## Performance and Input

### Smooth Movement and Stable Viewmodels

Keyboard movement now interpolates using the Simulation owner's actual fixed-tick fraction rather than guessed browser timing or an additional Worker query.

The measured movement max-to-median position-step ratio improved from 2.00 to approximately 1.02-1.07. Simulation remains near 66.7 ticks per second, movement adds zero standalone visibility requests, and frame percentiles do not regress.

Rapid mouse movement no longer makes the weapon float as though nondefault viewmodel sway were enabled. Fixed headed captures changed 98.0% of the world region while only 0.18% of weapon-region pixels exceeded an RGB tolerance of two; viewmodel yaw and pitch error remained exactly zero.

Related pull request: [#36](https://github.com/Hona/playsrc/pull/36).

### Every Mouse Movement Is Preserved

Displayed camera angles, view revisions, mouse revisions, and teleport revisions are now captured as one coherent presentation state before asynchronous rendering.

The complete headed browser verifier retained all 152 of 152 mouse events. Accelerated stress retained all 1,818 of 1,818 events across 12 rounds without adding Worker calls, slowing simulation, or changing first-person weapon alignment.

Related pull request: [#38](https://github.com/Hona/playsrc/pull/38).

### Faster, More Representative Profiling

Ordinary headed gameplay profiling skips unrelated startup movies and observes a bounded five-to-ten-second real gameplay window instead of repeatedly monopolizing the browser for several minutes.

A representative run recorded 6.364 seconds of active gameplay, 345 rendered frames, approximately 68 simulation ticks per second, and a 2.470 ms 95th-percentile measured frame. The map and menu profiles retain their own relevant visibility, HUD, input, and frame-time metrics.

Related pull request: [#39](https://github.com/Hona/playsrc/pull/39).

## Packaging and Delivery

The release now publishes one exact shared TF2 WASM object and one three-map catalog for `jump_beef`, `pl_upward`, and `ctf_2fort`.

Each map retains its original BSP, immutable resource graph, exact dependency ledger, and complete content-addressed chunk closure. Release descriptors are regenerated from the current merged implementation before publication; no prior release's asset hashes are reused after the game changes.

## Current Scope

- Gameplay is local single-player and bot-based; human networked multiplayer is not included.
- 2Fort's Capture the Flag rules are available; its authenticated bot navigation still depends on an authoritative 2Fort NAV mesh.
- `pl_upward` includes real map entities, track movement, bots, combat, and round state, but its complete physics-driven Payload cart and breakable constraint are not yet implemented.
- The Stickybomb Launcher and fully simulated grenade trajectories remain blocked on exact Source VPhysics rigid-body parity.
- Medic and Spy class foundations are present, but unfinished stock loadouts are not part of this release unless their changes merge before the release candidate is finalized.
