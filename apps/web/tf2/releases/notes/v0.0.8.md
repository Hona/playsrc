# playsrc v0.0.8

This update makes complete local Team Fortress 2 bot matches playable on 2Fort, adds the Medic's full stock loadout and Engineer buildings, restores missing world geometry and lighting, and fixes the default in-game HUD.

Every configured map now initializes in under seven seconds in the verified headed loading scenario. The release also removes multiple gigabytes of duplicated browser, Worker, WASM, and GPU allocations while preserving the original assets, simulation rate, and visible detail on `jump_beef`, `pl_upward`, and `ctf_2fort`.

## Local Matches and Bots

### Complete 2Fort Capture the Flag Matches

2Fort now supports a complete local RED-versus-BLU match rather than exposing separate objective, bot, and interface components that cannot reliably finish a round together.

Players can start a match from the authored Create Server interface, choose a team and class, and play alongside bots representing all nine stock classes. Bots leave their authored spawn rooms, navigate the map, use their available stock weapons, fight opponents, collect health and ammunition, pursue intelligence, respawn, and contribute to the live scoreboard.

Enemy briefcases can be carried through the original map routes and captured until a real team victory occurs. The victory screen, objective state, team scores, player rows, and class presentation are driven by the same authoritative local match.

A complete visibly headed BLU-victory run retained all nine stock classes, 67.5 simulation ticks per second, a 16.785 ms 95th-percentile displayed frame, and no frames longer than 33 ms.

Related pull request: [#118](https://github.com/Hona/playsrc/pull/118).

### Authenticated 2Fort Navigation

2Fort now uses its actual Source-generated, fully analyzed navigation mesh instead of an invented route graph or an unavailable navigation placeholder.

The authenticated NAV contains 1,128 areas, 4,233 directed connections, 385 hiding spots, and 32,700 visibility references. Its 307,701 bytes match SHA-256 `6c1e5b37b3cffb9ad97c554aa9e104119a5c5fb38bd6c9d2903a4d405f609017`.

Both teams can route from their authored spawns to enemy intelligence and back to their own capture areas. The implementation preserves Source's 300-unit navigation grid, all nine bot classes, existing Upward navigation, team-filtered spawns, and Spy combat.

A headed capture observed 32,820 changed visible player-model pixels and 66.64 simulation ticks per second across 5.012 seconds of real gameplay.

Related pull request: [#96](https://github.com/Hona/playsrc/pull/96).

### Practice and Create Server

The authored Find a Game, Training, Offline Practice, and Create Server paths now launch real local bot matches using configured maps and actual team/class selection.

Bot counts, Easy/Normal/Hard/Expert difficulty, quarter-second quota updates, normal/fill/match balancing, and console bot settings are owned by the local game rather than a decorative menu. Existing combat, respawns, intelligence captures, scoreboard updates, and victory transitions continue after the menu closes.

Headed verification exercised authored Training and Create Server dialogs, four balanced Hard bots, a real enemy kill, player death and respawn, three intelligence captures, and RED victory at 67.47 simulation ticks per second.

## Loading and Memory

### Every Map Initializes in Under Seven Seconds

Map initialization now decodes authored StudioModel animations lazily, parses bounded BSP lumps concurrently, inflates verified resource chunks directly into shared output, overlaps source-section loading with Worker decoding, and reuses authenticated model presentations across map changes.

The visibly headed three-map benchmark measures map initialization separately from network downloads and retains complete authored scene pixels:

- `jump_beef`: 21.986 seconds before, 4.492 seconds after; model decoding improves from 16.414 seconds to 0.832 seconds.
- `pl_upward`: 21.548 seconds before, 6.423 seconds after; model decoding improves from 13.954 seconds to 0.309 seconds.
- `ctf_2fort`: 27.194 seconds before, 6.572 seconds after; model decoding improves from 15.063 seconds to 0.241 seconds.

All three BSP identities, configured models, static props, textures, mip levels, animation frames, collision data, bots, water effects, and visible output remain intact. A separate headed Upward traversal retained 66.045 simulation ticks per second and a 17.425 ms displayed-frame 95th percentile.

The preceding loading pass had already reduced initialization from 28.775 to 21.986 seconds on `jump_beef`, 27.247 to 21.548 seconds on `pl_upward`, and 35.110 to 27.194 seconds on `ctf_2fort` before the final sub-seven-second implementation.

Related pull requests: [#124](https://github.com/Hona/playsrc/pull/124) and [#97](https://github.com/Hona/playsrc/pull/97).

### Shared Browser, Worker, and WASM Map Ownership

Authored Source resource graphs now enter gameplay through bounded 32 MiB sections backed directly by shared WASM linear memory. Browser presentation, the gameplay Worker, StudioModel parsing, VTF texture views, and collision/session owners reuse those verified bytes instead of cloning complete maps into multiple large buffers.

Old map generations retire atomically, including stale scene ownership, GPU textures, animation models, particles, collision state, and cached output. Cross-map model cache hits reuse authenticated presentations rather than reparsing matching source models.

A visibly headed three-map ownership profile reported these complete browser peak-residency changes:

- `jump_beef`: 6.51 GiB before, 4.00 GiB after; gameplay WASM falls from 2.40 GiB to 1.35 GiB.
- `ctf_2fort`: 7.94 GiB before, 6.63 GiB after; gameplay WASM falls from 3.86 GiB to 2.23 GiB.
- `pl_upward`: 7.54 GiB before, 5.84 GiB after; gameplay WASM falls from 2.94 GiB to 1.73 GiB.

Those owner-local measurements include approximately 38 MiB of additional authored content per map in the final build. All 2,265 2Fort props, all 1,244 Upward props, real visible world depth, local bots, water, and normal simulation cadence remain present.

Related pull request: [#122](https://github.com/Hona/playsrc/pull/122).

- Preserve animated world texture lifetime when changing maps or reusing authenticated model sources.
- Keep authored underwater refraction visible after bounded texture-frame eviction and GPU compression.
- Restore Soldier eye materials and selected local cubemaps without rebuilding unrelated shaders.
- Preserve Source sound samples, material-specific bullet impact audio, and configured hit-sound overrides.
- Keep team/class selection available before gameplay, HUD, and loading profilers begin sampling.

- Reset derived browser storage between full authored-map profile runs without changing gameplay cache semantics.
- Avoid diagnostic exception storms, duplicated simulation snapshots, and unnecessary browser-to-Worker byte comparisons.

## Current Scope

- Gameplay is local single-player and bot-based; human networked multiplayer is not included.
- 2Fort supports authored nine-class bot navigation, complete Capture the Flag objectives, local match victories, and the configured practice interface.
- `pl_upward` retains authored map entities, track movement, bots, combat, and round state, but its complete physics-driven Payload cart and breakable constraint are not implemented.
- Demoman's Bottle is playable, but the Stickybomb Launcher and fully simulated pipe-grenade trajectories remain unavailable until exact Source rigid-body behavior is complete.
- Only `jump_beef`, `pl_upward`, and `ctf_2fort` are configured release maps.
