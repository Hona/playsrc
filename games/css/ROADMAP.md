# Counter-Strike: Source Game Roadmap

[`../../docs/roadmap-contract.md`](../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../TERMINOLOGY.md`](../../TERMINOLOGY.md) defines game, ruleset, delivery status, coverage classification, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 42 behavior rows. [`inventories/behavior-families.md`](inventories/behavior-families.md) is a 42-item candidate index over the same stable row identities; it has no generator or accepted review and therefore contributes no additional denominator identities. The current completion denominator is exactly 42 items.

The denominator covers CS:S-owned player, team, class, inventory, economy, damage, weapon, grenade, C4, movement-specialization, entity, objective-primitive, common-rule, prediction, replicated-state, replay-interpretation, game-event, user-message, and presentation-mapping behavior over generic Source packages. Mode lifecycle, objective policy, scoring, spawning restrictions, completion, and wins belong to [`rulesets/ROADMAP.md`](rulesets/ROADMAP.md).

The denominator is Not accepted. The selected CS:S content build, runtime capture set, declaration-inventory generator, ruleset denominator, arithmetic profile, and required generic package interfaces are unavailable.

## Inputs

- One immutable prior CS:S state with stable simulation tick and identities for players, teams, classes, accounts, health, armor, equipment, ammo, inventory, active weapons, accuracy and recoil, grenade projectiles, C4, hostages, game entities, objective primitives, common game rules, prediction, and replicated-field source values.
- One ordered admitted-command set supplied by Simulation. Commands contain the current Movement command fields plus game-owned team/class selection, buying, weapon selection, attack, reload, alternate action, use, drop, radio, and observer requests. CS:S validates game meaning and cannot decode transport bytes or schedule ticks.
- One positive finite fixed tick interval, simulation time, deterministic random-stream identity and state for every game-owned draw, and one immutable snapshot of every consumed game configuration value.
- Exactly one selected CS:S ruleset policy. It supplies only mode lifecycle, objective eligibility and scoring, spawn restrictions, completion, and win decisions; it cannot replace CS:S-wide mechanics.
- One exact CS:S content-build input resolved through Content: game identity; build identity; `gameinfo.txt`; weapon scripts; game-event declarations; FGD; map entity data; models; animations; materials; sounds; particles; and every per-map game configuration, each with logical path, provider identity, source location, and SHA-256. No such build is currently configured.
- Current generic-package interfaces for Movement, Collision, Physics, Entity, Simulation, Networking, Replay, Content, Material, Rendering, Particle, and Audio. CS:S never substitutes another implementation for those packages.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a` for generic Source player, teamplay, weapon, damage, entity, movement, prediction, networking-declaration, and game-event seams. Its game-code tree does not define the CS:S-owned denominator.
- Valve Steam application `240` identifies the CS:S product. The Store API response checked on 2026-07-16 exposes no immutable content-build identity; the target revision is therefore Unknown.

## Outputs

- One immutable next CS:S state containing every advanced game-owned field and stable references to unchanged generic state.
- One ordered gameplay journal containing player/team/class, inventory/economy, damage/death, weapon/grenade/C4, movement-specialization, entity, objective-primitive, common-rule, and ruleset-request facts.
- One canonical replication source and prediction result for every accepted logical CS:S field, without wire encoding or transport state.
- One ordered game-event and user-message journal with exact typed payloads, recipient facts, and gameplay or presentation disposition.
- Typed presentation requests selecting player, weapon, projectile, C4, hostage, objective, model, skin, bodygroup, animation, viewmodel, particle, decal, and script-sound resources from authoritative or replay facts.
- A structured failure naming operation, tick, stable identity, input or package-query identity, violated invariant, offending value, configured limit, and exactly one `Malformed`, `Unsupported`, `Unknown`, or `Missing` classification. Failure publishes no partial authoritative next state.

## Invariants

- Simulation is the sole gameplay authority. Authoritative and predicted execution invoke the same CS:S transition; rendering, replay, networking transport, applications, and presentation cannot advance or repair gameplay.
- Every accepted team, player state, class, weapon, equipment item, ammo type, entity class, objective primitive, configuration value, replicated field, prediction field, event, user message, and presentation mapping has one stable identity and one coverage classification.
- Terrorist and Counter-Terrorist are the only active combat-team identities. Unassigned, spectator, automatic selection, invalid values, and sentinels retain explicit non-combat dispositions.
- Account changes, prices, purchase eligibility, inventory mutation, round rewards, penalties, and dropped-item ownership advance through one ordered ledger. No application or UI can mutate money or equipment directly.
- Damage admission, hitgroup scaling, armor and helmet absorption, friendly-fire policy, health mutation, death attribution, drops, rewards, and emitted events execute once in declared order.
- Weapon attacks, reloads, alternate actions, accuracy, recoil, spread, penetration, clips, reserves, projectile creation, impact, detonation, C4 actions, and use progress use simulation time and the supplied deterministic random streams.
- Movement truth comes only from Movement and Collision. CS:S supplies game-owned speed, stamina, velocity-modifier, duck, jump, ladder, surface, equipment, freeze, and collision policy and consumes the generic result once.
- CS:S entities consume generic Entity state, I/O, touch, trigger, parenting, mover, and lifecycle facts. Game entities cannot implement another entity queue, collision query, physics solve, or ruleset lifecycle.
- Hostage, C4, buy-zone, rescue-zone, escape-zone, VIP-safety, spawn, and scenario facts are reusable CS:S primitives. A selected ruleset exclusively owns mode progression, score, restrictions, completion, and wins.
- Replicated fields derive from canonical state once per publication boundary. Replay maps decoded recorded fields to CS:S meaning and never resimulates absent gameplay.
- Presentation mappings are pure functions of canonical CS:S or replay state plus immutable content. Frame rate, interpolation, animation sampling, particles, audio, and HUD state cannot affect gameplay or replay truth.
- Every variable-sized collection and operation is bounded by accepted configuration or the owning generic-package contract. Limit-plus-one fails before mutation; truncation is never a successful result.
- No fallback implementation, compatibility layer, legacy schema branch, duplicate game authority, ambient installation discovery, or stale inventory is permitted.

## Ownership Exclusions

- KeyValues, VPK, StudioModel, BSP, VTF, VMT, PHY, and Demo own format parsing. Content owns logical-path/provider resolution. CS:S owns interpretation of successfully parsed CS:S game content.
- Movement owns generic command movement, hull motion, ground, air, water, ladder, crouch, stair, clipping, noclip, observer, toss, and mover-carry behavior. CS:S owns only its game-selected values, eligibility, modifiers, collision policy, and post-result state/events.
- Collision owns geometric query truth. Physics owns rigid bodies, persistent contacts, constraints, and solver response. Entity owns generic lifecycle, hierarchy, I/O, triggers, touch, movers, and rollback publication. CS:S owns game-specific filters, masks, eligibility, damage, and responses.
- Simulation owns command admission, fixed-tick scheduling, random-stream provisioning, transition boundaries, and publication. Networking owns wire encoding, tables, baselines, deltas, acknowledgement, recipients, and reconciliation mechanics.
- Replay owns recorded-byte decoding, timeline advancement, seeking, and replay snapshots. CS:S owns semantic interpretation of decoded CS:S classes, fields, entities, events, and messages.
- Rendering, Particle, and Audio own presentation execution. CS:S owns only mappings from game facts to typed requests.
- [`rulesets/ROADMAP.md`](rulesets/ROADMAP.md) owns every mode-only lifecycle, objective policy, score, spawn restriction, round restriction, completion, win, and mode-state transition.
- Applications own input bindings, menus, HUD layout, camera presentation, settings, catalogs, and product assembly. Services own hosted processes and transport endpoints. Tools own inventory generation and evidence orchestration.
- Bots and navigation AI, achievements, persistent statistics, voting and administration, dynamic market pricing, seasonal rewards, and vehicle driving are excluded until a declared Future product experience adds them to this denominator. Encountered declarations remain classified.
- Legacy CS:GO differences, TF2 behavior, Source 2, legal/publication classification, and content acquisition are excluded.
