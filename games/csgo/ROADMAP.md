# Legacy Source 1 CS:GO Game Roadmap

[`../../docs/roadmap-contract.md`](../../docs/roadmap-contract.md) defines the normative roadmap schema and denominator review gate. [`../../TERMINOLOGY.md`](../../TERMINOLOGY.md) defines game, ruleset, delivery status, coverage classification, inventory, and completion terms.

## Completion Denominator

This leaf roadmap contains exactly 49 behavior rows. [`inventories/behavior-families.md`](inventories/behavior-families.md) is a 49-item candidate index over the same stable row identities; it has no generator or accepted review and therefore contributes no additional denominator identities. The current completion denominator is exactly 49 items.

The target build range contains exactly one legacy Source 1 build: engine build `8802`, protocol `13881`, client/server version `1575`, patch `1.38.8.1`, Source revision `8413246`, compiled 24 August 2023 and packaged by the final `steam.inf` identity dated 12 October 2023. Steam application `730` branch `csgo_legacy`, common depot `731` manifest `1224088799001669801`, and Windows depot `732` manifest `6314304446937576250` identify the target bytes. Earlier CS:GO builds and every Source 2 build are outside this denominator.

The denominator covers legacy CS:GO-owned player, team, agent/class, item-schema, loadout, inventory, economy, damage, weapon, equipment, projectile, C4, movement-specialization, entity, bot, objective-primitive, common-rule, prediction, replicated-state, replay-interpretation, event, message, and presentation-mapping behavior over generic Source packages. Mode lifecycle, objective policy, scoring, spawning restrictions, completion, and wins belong to [`rulesets/ROADMAP.md`](rulesets/ROADMAP.md).

The denominator is Not accepted. Exact target depot bytes and hashes, controlled runtime captures, the inventory generator, the ruleset denominator, the arithmetic profile, and required generic package interfaces are Missing or Blocked.

## Inputs

- One immutable prior legacy CS:GO state with stable simulation tick and identities for players, teams, agents/classes, accounts, health, armor, equipment, item definitions and instances, loadouts, ammo, weapon accuracy/recoil, projectiles, C4, hostages, bots, game entities, objective primitives, common game rules, prediction, and replicated-field source values.
- One ordered admitted-command set supplied by Simulation. Commands contain the current Movement command fields plus team selection, loadout and buy requests, weapon selection, attack, reload, alternate action, use, drop, radio, observer, and bot-control requests. Legacy CS:GO validates game meaning and cannot decode transport bytes or schedule ticks.
- One positive finite fixed tick interval, simulation time, deterministic random-stream identity and state for every game-owned draw, and one immutable snapshot of every consumed legacy CS:GO configuration value.
- Exactly one selected legacy CS:GO ruleset policy. It supplies only mode lifecycle, objective eligibility and scoring, spawn restrictions, completion, and win decisions; it cannot replace game-wide mechanics.
- The exact target content/build identity above, resolved through Content. Required logical inputs include `steam.inf`, `gameinfo.txt`, `gamemodes.txt`, mode CFGs, `scripts/items/items_game.txt`, weapon and equipment data, game-event declarations, FGD, NAV files used by accepted bot scenarios, map entity data, models, animations, materials, sounds, and particles, each with provider identity, source location, and SHA-256.
- Current generic-package interfaces for KeyValues, VPK, StudioModel, BSP, VTF, VMT, PHY, Demo, NAV, Content, Map, Material, Entity, Collision, Visibility, Movement, Physics, Simulation, Networking, Replay, Rendering, Particle, and Audio. Legacy CS:GO never substitutes another implementation for those packages.
- Valve Source SDK 2013 commit `88fa198fba3fb85d46d4c95018254693fdc3af0a` for generic Source player, teamplay, weapon, damage, entity, movement, prediction, navigation, networking-declaration, and event seams. These seams do not establish legacy CS:GO-specific values or transitions.
- Valve's `ValveSoftware/csgo-demoinfo` commit `049f8dbf49099d3cc544ec5061a7f7252cce7b82` for the published CS:GO demo/network protobuf framing and message contracts. Final-build runtime captures must establish additions, removals, and field behavior at protocol `13881`.
- SteamTracking's immutable legacy declaration snapshot `e63fc7fdb8dfb4f1873f0db214c0cc16613d5beb` for patch `1.38.7.9` is a candidate discovery input only. A declaration enters this target only after exact target-manifest bytes or a controlled `1.38.8.1` capture proves the same identity and behavior.

## Invariants

- Simulation is the sole gameplay authority. Authoritative and predicted execution invoke the same legacy CS:GO transition; rendering, replay, networking transport, applications, and presentation cannot advance or repair gameplay.
- Every accepted player state, team, agent/class, schema record, item, loadout slot, weapon, equipment item, ammo type, projectile, entity class, bot profile, objective primitive, configuration value, replicated field, prediction field, event, user message, and presentation mapping has one stable identity and one coverage classification.
- Terrorist and Counter-Terrorist are the only active combat-team identities. Unassigned, spectator, automatic selection, Danger Zone squad identities, invalid values, and sentinels retain explicit context-specific dispositions.
- Item-schema and loadout processing preserves declaration order, duplicate occurrence, prefab inheritance, definition identity, team eligibility, slot eligibility, and content provenance. Account inventory, market, trading, crafting, and drop entitlement cannot alter gameplay unless an explicit supplied item instance is accepted.
- Account changes, prices, purchase eligibility, inventory mutation, round rewards, penalties, and dropped-item ownership advance through one ordered ledger. No application or UI can mutate money or equipment directly.
- Damage admission, hitgroup scaling, armor and helmet absorption, friendly-fire policy, health mutation, tagging, death attribution, drops, rewards, and emitted events execute once in declared order.
- Weapon attacks, reloads, alternate actions, accuracy, recoil, spread, penetration, clips, reserves, projectile creation, impact, detonation, C4 actions, and use progress use simulation time and supplied deterministic random streams.
- Movement truth comes only from Movement and Collision. Legacy CS:GO supplies game-owned hull/view values, speed, stamina, velocity modifier, duck, jump, ladder, water, surface, equipment, freeze, tagging, and collision policy and consumes the generic result once.
- Game entities consume generic Entity state, I/O, touch, trigger, parenting, mover, and lifecycle facts. Game entities and bots cannot implement another entity queue, geometric query, physics solve, navigation parser, or ruleset lifecycle.
- Hostage, C4, buy-zone, rescue-zone, spawn, survival-zone, course-zone, and scenario facts are reusable legacy CS:GO primitives. A selected ruleset exclusively owns mode progression, score, restrictions, completion, and wins.
- Bot decisions consume one immutable NAV representation, game state, ruleset policy, tick context, and named random state. Bot behavior cannot mutate human commands, navigation bytes, collision truth, or gameplay outside the same game transition.
- Replicated fields derive from canonical state once per publication boundary. Replay maps decoded recorded fields to legacy CS:GO meaning and never resimulates absent gameplay.
- Presentation mappings are pure functions of canonical legacy CS:GO or replay state plus immutable content. Frame rate, interpolation, animation sampling, particles, audio, and HUD state cannot affect gameplay or replay truth.
- Every variable-sized collection and operation is bounded by accepted configuration or the owning generic-package contract. Limit-plus-one fails before mutation; truncation is never a successful result.
- No fallback implementation, compatibility layer, legacy schema branch, duplicate game authority, ambient installation discovery, or stale inventory is permitted.

## Ownership Exclusions

- KeyValues, VPK, StudioModel, BSP, VTF, VMT, PHY, Demo, and the proposed NAV package own format parsing. Content owns logical-path/provider resolution. Legacy CS:GO owns interpretation of successfully parsed game content.
- Movement owns generic command movement, hull motion, ground, air, water, ladder, crouch, stair, clipping, noclip, observer, toss, and mover-carry behavior. Legacy CS:GO owns only its selected values, eligibility, modifiers, collision policy, and post-result state/events.
- Collision owns geometric query truth. Physics owns rigid bodies, persistent contacts, constraints, and solver response. Entity owns generic lifecycle, hierarchy, I/O, triggers, touch, movers, and rollback publication. Legacy CS:GO owns game-specific filters, masks, eligibility, damage, responses, and bot decisions.
- Simulation owns command admission, fixed-tick scheduling, random-stream provisioning, transition boundaries, and publication. Networking owns wire encoding, tables, baselines, deltas, acknowledgement, recipients, and reconciliation mechanics.
- Replay owns recorded-byte decoding, timeline advancement, seeking, and replay snapshots. Legacy CS:GO owns semantic interpretation of decoded classes, fields, entities, events, and messages.
- Rendering, Particle, and Audio own presentation execution. Legacy CS:GO owns only mappings from game facts to typed requests.
- [`rulesets/ROADMAP.md`](rulesets/ROADMAP.md) owns every mode-only lifecycle, objective policy, score, spawn restriction, round restriction, course/timer transition, completion, win, and mode-state transition.
- Applications own input bindings, menus, HUD layout, camera presentation, settings, catalogs, and product assembly. Services own hosted processes, matchmaking, skill ratings, durable records/rankings, Game Coordinator integration, and transport endpoints. Tools own inventory generation and evidence orchestration.
- Premier map veto, queue eligibility, skill groups, trust/Prime policy, penalties outside a live match, persistent statistics, achievements, account progression, market/store behavior, seasonal rewards, and anti-cheat enforcement are excluded from game advancement. Their encountered declarations remain classified.
- CS:S differences, TF2 behavior, Source 2, console-port behavior, legal/publication classification, and content acquisition are excluded.
