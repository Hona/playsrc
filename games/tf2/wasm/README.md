# TF2 WASM Binding

The TF2 browser binding compiles transferred BSP/configuration bytes through the shared Map, Entity, Collision, and Visibility Rust crates and initializes one game-owned session at the first `info_player_teamspawn`; a missing or malformed spawn fails compilation. Generation-checked handles own the deterministic map payload, TF2 state, latest snapshot, and explicit disposal. Worker termination is the cancellation boundary; no JavaScript callback runs inside parsing, compilation, collision, movement, or gameplay advancement.

`playsrc_compile_map` returns a handle for both success and classified failure. `playsrc_result_error` returns `0` for success, `1` for malformed BSP bytes, `2` for an unknown lighting profile, `3` for failed canonical map compilation, `4` for a missing or malformed TF2 spawn, and `5` for malformed or unresolved teleport entities. Successful map payload length, bytes, and SHA-256 are read through `playsrc_result_length`, `playsrc_result_copy`, and `playsrc_result_hash` before or during the session lifetime.

`playsrc_game_advance` accepts exactly one 24-byte little-endian command and advances it for 1 through 64 fixed ticks. Bytes 0, 4, 8, and 12 are finite binary32 forward move, side move, yaw degrees, and pitch degrees. The `u32` at byte 16 assigns jump, crouch, fire, and detonate to bits 0 through 3. The `u32` at byte 20 assigns class to bits 0 through 7 (`1` Soldier, `2` Demoman) and weapon to bits 8 through 15 (`1` Rocket Launcher, `2` Original, `3` Stickybomb Launcher). Unknown selectors retain the current selection. A malformed command, stale handle, failed game transition, zero ticks, or more than 64 ticks returns zero and leaves the session plus its prior snapshot unchanged.

The generation-bound snapshot starts with `PSSN`, little-endian version `2`, `u64` tick, class byte, weapon byte, grounded byte, crouched byte, six binary32 player position/velocity values, binary32 health, and a `u32` projectile count. Each 36-byte projectile contains `u32` identity, kind byte, armed byte, stuck byte, one reserved zero byte, three position values, three velocity values, and age. The following `u32` event count precedes 28-byte events: kind byte, detail byte, two reserved zero bytes, `u32` subject identity, `u32` auxiliary identity, and four binary32 values. Event kinds are class change, weapon change, fire, explosion, damage, blast impulse, respawn, and teleport as 1 through 8. Teleport subject/auxiliary identify trigger/destination entities, values contain destination position and yaw, and detail `1` applies that yaw. A bounded multi-tick call retains events from every advanced tick in tick order.
