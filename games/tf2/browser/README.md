# TF2 Browser Adapter

The adapter owns the browser worker boundary for the game-owned TF2 WASM module. One worker verifies at most 64 MiB of transferred WASM bytes against their SHA-256, compiles one transferred BSP of at most 512 MiB with at most 64 MiB of exact configuration/dependency bytes, retains one generation-checked gameplay session, returns the canonical map payload as one transferable buffer of at most 64 MiB only on a derived-cache miss, returns one selected-teamspawn descriptor, atomically configures one 52–65,536-byte map-hash-bound linear Jump course, advances 1 through 64 fixed ticks per 40-byte version-2 command, and returns one transferable version-3 snapshot of at most 64 MiB per phase. The client permits at most 64 pending requests. The application owns immutable-object fetching, pacing, physical input bindings, course acquisition, routing, IndexedDB lifetime, and worker termination.

The command carries forward/side/up movement, yaw/pitch, jump/crouch/speed, fire/detonate/reload/reset/respawn, class/team/weapon/mode requests, and one explicit map-entity activation identity. The snapshot carries the complete 96-byte Movement state, stock loadout/ammo/reload state, current inline-model transforms, ordered Entity I/O/contact/mover events, Jump run/events/result, gameplay events, and the frozen projectile producer record. Every count, section, enum, finite scalar, quaternion, normal, projectile transition, reserved byte, and final byte offset is validated before publication.

`mapDerivedKey` is the lowercase SHA-256 of UTF-8 `playsrc-map-runtime-2\n<BSP SHA-256>\n<lighting profile integer>\n<configuration SHA-256>\n`. A cache hit supplies presentation bytes only after the staged worker compilation reports the same payload length and SHA-256. A cache miss copies the staged payload once, verifies and stores it, then activates the session. Cache corruption, transfer failure, or write failure discards the staged handle and preserves the prior active generation.

The existing `tf2Presentation` consumer predates the version-3 projectile contract. Stage 3 must consume `identity`, `team`, `state`, `orientation`, `angularVelocity`, and `contactNormal` directly and consume `projectileEvents`; deriving model angles from velocity is prohibited. Gameplay selects no model, skin, particle, color, sound, or browser resource.
