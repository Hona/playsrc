# TF2 Browser Adapter

The adapter owns the browser worker boundary for the game-owned TF2 WASM module. One coordinator worker verifies at most 64 MiB of transferred WASM bytes, initializes the bounded shared-memory Rayon pool from `navigator.hardwareConcurrency`, compiles one transferred BSP/configuration pair, atomically stages canonical map plus PTF2 v12 presentation bytes in one response, accepts an externally authoritative map-bound course when supplied, advances bounded fixed ticks, executes complete Particle, Visibility/Water, and StudioModel pose/composition phases, and transfers each bounded result once. Same-turn model and exact Visibility preparation share one Worker request while retaining independently ordered responses; exclusively owned resource/BSP/command/pose/particle buffers transfer without pre-copying, bounded PSIM/PSSN/Collision and aligned PVIS sections remain views over their transferred buffers, authenticated map/presentation cache lookups overlap, and synchronous Worker transactions dispatch without a promise-chain queue. The bounded presentation decoder validates `PSPA`/`PVHA`, retains typed-array occurrence/color/light records, and supplies static-prop rendering without per-prop WASM calls. PVIS v4 independently supplies PVS and render-camera origins plus an optional exact area. Browser UI resources separately validate the PUIB-owned chapter-1 `background_2fort` standard/widescreen GameUI descriptor against exact material/texture records. The client permits at most 64 pending requests. The application owns immutable-object fetching, pacing, physical input bindings, routing, IndexedDB lifetime, and worker termination.

PCMD v4 carries forward/side/up movement, yaw/pitch, jump/crouch/speed, fire/detonate/reload/reset/respawn, class/team/weapon/mode requests, one map-entity activation identity, and bounded typed sticky-Physics results only. PSSN v9 additionally carries exact retained Source player flags, canonical water type, restorable TF2 random state, every typed draw, producer-selected audio events/samples/wave ordinals, immutable Collision v3 snapshot bytes, consumed rocket results, ordered mover results, and locker animation facts. Browser random, wave, rocket, and mover selectors do not exist. No prior command or snapshot reader remains.

`mapDerivedKey` uses compiler contract `playsrc-map-runtime-9`; presentation cache identity uses `playsrc-tf2-presentation-v12`. Every cache read verifies its retained SHA-256, staged compilation requires the exact current byte length, and corruption or transfer failure discards the staged handle and preserves the prior generation.

## Worker transport roadmap

| Source/TF2 behavior | playsrc behavior | Evidence | Status |
| --- | --- | --- | --- |
| Preserve every ordered predicted command, fixed tick, weapon event, projectile attachment, visibility decision, world pass, and post-world viewmodel pass | Fuse staged map/presentation delivery, overlap authenticated cache lookups, transfer owned request buffers, decode bounded snapshots from transferred byte ranges, coalesce same-turn pose/visibility preparation, dispatch synchronous Worker messages without a promise-chain stall, and retain atomic generation replacement and cleanup | Valve Source SDK 2013 `src/game/client/prediction.cpp`, `src/game/client/viewrender.cpp`, `src/game/client/tf/c_tf_projectile_rocket.cpp`; `tests/worker-pipeline.test.ts`; visibly headed `jump_beef` gameplay, movement, mouse-look, and projectile capture | Complete |

The production resource-batch boundary is 512 MiB. Exact `pl_upward` supplies 381,261,329 bytes after the graph's bounded decode, including the single PVHA aggregate; the prior 256 MiB adapter limit was smaller than the accepted production object and is removed in both client and Worker admission.

All wasm32 allocation results are normalized to unsigned addresses before JavaScript memory views, including schema-5 `pl_upward` outputs above the signed 31-bit interval. The browser labels and reloads the active configured target and never substitutes `jump_beef`.

Projectile presentation consumes an immutable strictly ordered per-tick fact/event timeline, so a projectile created and removed inside one host publication does not need to survive in its final active set. Sky-removed rockets arrive as non-explosive terminal-plus-destroy transitions. PPTX v2 preserves each source tick, attachment-local trail controls, graceful trail stops, exact wall/mid-air explosion orientation, and local/non-local muzzle selection. Stock stickies preserve their transported VPhysics quaternion and remain hidden for their first `0.1` seconds. Stock first-person requests compose the Soldier/Demoman hand animation model with the configured item `c_model`, shared team skin, copied matching bones, reconstructed unmatched bones, and separate hand/item draw parts; Rendering isolates that post-world pass from world depth while retaining hand/item self-depth. No legacy `v_model` path remains.

`src/presentation.ts` includes viewmodel-bob behavior adapted from Valve Source SDK 2013 and is subject to the Source 1 SDK License and notices retained under `packages/presentation/particle`.

The all-class item/schema/attribute/condition/health/damage/pickup core remains in the owning `playsrc-tf2` package. This adapter continues to expose the current compact direct-map Soldier/Demoman session until a complete replacement protocol can consume that core without creating a second gameplay authority. It contains no Demo, Networking, or Replay application adapter.
