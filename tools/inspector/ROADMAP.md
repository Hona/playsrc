# Inspector Roadmap

[`../../docs/roadmap-contract.md`](../../docs/roadmap-contract.md) defines evidence and denominator-review requirements. [`../../TERMINOLOGY.md`](../../TERMINOLOGY.md) defines gameplay authority, replay authority, presentation state, evidence, coverage classification, bound, current contract, and Complete.

## Completion Denominator

The completion denominator contains exactly the 16 Behavior Families rows below: map, format, material, model, entity, collision, visibility, movement, physics, simulation, networking, replay, rendering, particle, audio, and evidence views.

Those rows require exactly 23 seams: Map; KeyValues, BSP, VPK, VTF, VMT, PHY, and Demo format outputs; StudioModel; Material; Entity; Collision; Visibility; Movement; Physics; Simulation; Networking; Replay; Rendering; Particle; Audio; the roadmap evidence-record contract; and the hosting application's read-only observation adapter. The denominator is Not accepted because the 15 domain view families depend on 21 domain-owner interfaces that are Not accepted or unimplemented and no review record exists.

The executable entry point is exactly `bun run inspect <target>`. `<target>` is the one logical inspection target described under Inputs; no routine path, owner implementation path, output root, executable path, limit, or concurrency policy is accepted as an argument.

## Inputs

- One stable logical inspection target resolved through an accepted owner registry. It names an immutable artifact/snapshot/query identity or one read-only live session plus its owner, current interface identity, content build, source hashes, coverage classifications, and timeline coordinate when applicable.
- Current owner outputs and structured failures only: `CanonicalMap`, format documents and diagnostics, `ResolvedMaterial` and evaluated state, `StudioModelDocument`, Entity definitions/world/transitions/snapshots, Collision worlds/snapshots/query results, Visibility worlds/revisions/query results, Movement commands/states/results, Physics worlds/transitions/snapshots, Simulation sessions/phase records/events/snapshots, Networking connection/message/observation state, Replay sessions/cursors/events/snapshots, Rendering scene/frame/resource/capture results, Particle registries/world/render outputs, and Audio registries/events/voices/observations.
- The seven format-view owners are exactly KeyValues, BSP, VPK, VTF, VMT, PHY, and Demo. StudioModel enters the separate model view and is not duplicated by the format view.
- One application-owned observation adapter for attaching to a live owner, submitting an owner-declared read/query/pause/step/seek request, receiving immutable observations, and detaching. The adapter cannot expose a mutable owner object.
- One checked `InspectorPolicy` containing accepted host/browser profiles plus `InspectionLimits` with positive integer maxima for open views, in-flight owner requests, queued observations, retained owner bytes, table rows per page, timeline samples, overlay primitives, selected identities, exported bytes, diagnostics, and session duration. No command overrides the policy and no view has an unbounded mode.
- Optional current evidence records with every field required by the roadmap contract and immutable retained artifacts referenced by exact identity and hash.

## Outputs

- One `InspectionSession` in exactly `Opening`, `Ready`, `Failed`, or `Closed`, with target, owner, interface, attachment, limits, and current observation identities. Failure publishes no partial Ready session.
- One or more bounded `InspectionView` values containing view-family identity, exact owner payload identity and hash, selected item identities, owner field names and values, coverage classifications, source/provenance links, timeline coordinate, display-only filter/sort/camera state, and diagnostics.
- Owner-provided tables, trees, graphs, timelines, plots, query results, debug primitives, pixels, waveforms, and retained evidence artifacts. Inspector labels every display-only projection and retains access to the exact owner value from which it was drawn.
- An immutable `InspectionExport` encoded as canonical UTF-8 JSON and containing target, owner/interface identity, source payload hash, selected fields/items, timeline coordinate, display state, classifications, diagnostics, environment, and exact referenced artifact identities. It is diagnostic output, never a domain artifact, evidence claim, gameplay snapshot, replay snapshot, or map root.
- Failures use exactly `MalformedTarget`, `MissingTarget`, `OwnerUnavailable`, `OwnerRejected`, `StaleObservation`, `BoundExceeded`, `Cancelled`, or `PresentationFailure`, retain the nested owner error unchanged, and name the last complete observation identity.

## Invariants

- Inspector obtains semantic values only from the current owner interface. It never parses source bytes, resolves a material, assembles a map, computes collision or visibility truth, advances movement/physics/simulation/replay/particle/audio state, decodes networking, or prepares renderer draws independently.
- The executable resolves the repository root, checked Inspector policy, and local configuration from its installed location. Caller working directory, environment path overrides, and host path spelling cannot change the selected logical target or invariant output.
- Attaching, filtering, sorting, selecting, plotting, changing a diagnostic camera, exporting, and closing cannot mutate an owner. An interactive query, pause, step, seek, or reset request is sent through the declared owner/application interface; only the returned owner observation changes displayed domain state.
- Every observation carries owner, current interface, stable payload, source/content, coverage, and timeline identities. Inspector rejects a response for another target, interface, content hash, simulation tick, physics revision, network cursor, replay cursor, render frame, particle timestamp, audio revision, or evidence record.
- Gameplay, replay, and presentation coordinates remain distinct. Inspector never labels interpolation as gameplay state, a replay presentation fraction as an authoritative replay cursor, a render frame as a simulation tick, or an observation sample as a state transition.
- Display filtering and pagination never change the underlying count or classification. Over-bound data is paged through an owner interface or rejected before retention; it is never silently truncated and called complete.
- Collision, visibility, entity, movement, and physics debug geometry consists only of owner-supplied shapes, query inputs/results, stable identities, and transforms. Rendering owns pixels and debug drawing; Inspector owns only selection, labels, layout, and interaction.
- Source byte ranges and encoded values appear only when supplied by a format owner. Semantic views never reinterpret an opaque, Unknown, Unsupported, Malformed, or Missing record.
- Live observations are processed in owner sequence. Queue saturation applies backpressure or rejects attachment; it never drops an authoritative transition while presenting a later transition as contiguous. A view may explicitly sample presentation-only measurements when the gap is labeled with skipped sequence identities.
- Evidence views display the claim, authority, playsrc identity, inputs, configuration, environment, procedure, comparison, result, integration, and retained artifacts supplied by the owner record. Inspector never runs a corpus, updates a baseline, changes a tolerance, recomputes a pass result as authority, or turns manual inspection into automated evidence.
- Inspector-owned browser listeners, workers, GPU debug resources, audio observation nodes, owner subscriptions, buffers, and object URLs are bounded and released exactly once on target replacement, cancellation, failure, or close.

## Ownership Exclusions

- Each package, game, ruleset, application, and service retains the meaning, state, query, error, and evidence predicate behind its public interface. Inspector owns no inspector-only semantic fix, adapter fallback, compatibility reader, or alternate implementation.
- Rendering owns all ordinary and diagnostic pixels, GPU resources, frame submission, and captures. Inspector supplies a declared debug selection and presents returned results.
- Applications own routes, browser lifecycle, authentication, permissions, live-session attachment, and product controls. The playsrc tool owns repeated verification and process orchestration.
- Asset Store owns immutable artifact retrieval and integrity. Content owns exact Source logical-path resolution. Inspector cannot scan either store or resolve a failed target through another root.
- Game-specific meanings remain in the selected game, and ruleset meanings remain in the selected game-owned ruleset. No standalone game or ruleset view enters the current denominator; their supplied fields appear in Simulation, Networking, Replay, presentation, or evidence views under the owning identity.
- VGUI, product UI inspection, authoring/editing, automated regression-corpus infrastructure, and production observability dashboards are outside this denominator.

## Generated Inventories

This roadmap owns no generated inventory. The 16 view families and one command identity are explicitly enumerated above. Their required seam count is exactly 23: 21 domain owner interfaces, one roadmap evidence-record contract, and one application observation adapter.

Large format, game, message, entity, material, particle, audio, and presentation universes remain generated inventories of their sole domain owners. Inspector consumes accepted stable identities and coverage classifications from those inventories and cannot generate or alter them.

## Exit Criteria

Inspector is Complete only when all of these predicates pass:

- All 16 Behavior Families rows are Ready and the denominator has an Accepted review record.
- All 23 required seams use accepted current interfaces and pass fixed adapter conformance evidence.
- Static and live sessions preserve owner identity, source/content hashes, timeline/revision continuity, classifications, bounds, backpressure, cancellation, and cleanup.
- Query controls invoke only owner interfaces; visual overlays and captures use Rendering output and retain exact owner result identities.
- Every owner-supplied Handled, Intentionally inert, Unsupported, Malformed, Unknown, and Missing state remains visible and is never repaired, suppressed, or reclassified by Inspector.
- Evidence display passes complete/missing-field, retained-artifact, manual-inspection, and bounded-export comparisons without running or changing evidence.
- Application integration proves no duplicate parser, resolver, map assembler, gameplay authority, replay authority, physics solver, network decoder, presentation simulator, renderer, audio graph, or evidence evaluator exists under Inspector.
- No required owner interface, inventory, observation adapter, browser/GPU profile, evidence record, or limit remains Unsupported, Unknown, Missing, Partial, or Blocked.

## Blockers

- **Domain owner interfaces:** Map; the seven format-view owners; StudioModel; Material; Entity; Collision; Visibility; Movement; Physics; Simulation; Networking; Replay; Rendering; Particle; and Audio have Not accepted denominators or no implementations. Checked every named roadmap, inventory, package tree, and the root Owner Registry.
- **Live observation adapter:** Active application and service roadmaps define bounded observation targets but expose no accepted Inspector attachment, pause/step/seek/query, sequence-continuity, backpressure, or detach interface. Checked `apps/**/ROADMAP.md`, current runtime and presentation roadmaps, and `tools/inspector/README.md`.
- **Upstream ownership conflicts:** Collision and Physics record an unresolved stateless/persistent contact boundary, and Physics records no adjacent owner for physical surface records. Their views cannot bind one stable field owner until those public roadmaps resolve the seams.
- **Map and artifact inputs:** Map and Asset Store are unimplemented, so no complete canonical map root or immutable artifact closure can drive static inspection. Checked both roadmaps and inventories.
- **Replay application owner:** Replay records no accepted application owner for a recorded-replay experience, preventing live application integration of the replay view. Checked Replay, TF2 and Tempus application READMEs, the root roadmap, and the Owner Registry.
- **Rendering environment:** no accepted browser, operating-system, GPU, driver, WebGPU feature/limit, or capture matrix exists for diagnostic pixels and resource evidence. Checked Rendering, Active web application READMEs, and the root roadmap.
