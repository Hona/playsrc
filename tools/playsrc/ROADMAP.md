# playsrc Tool Roadmap

[`../../docs/roadmap-contract.md`](../../docs/roadmap-contract.md) defines evidence and denominator-review requirements. [`../../TERMINOLOGY.md`](../../TERMINOLOGY.md) defines Tool, logical path, stale artifact, work directory, channel, bound, backpressure, current contract, and Complete.

## Completion Denominator

The completion denominator contains exactly the 24 Behavior Families rows below. The supported command surface contains exactly these 10 commands:

```text
bun run setup
bun run inventory <owner>
bun run compile <map>
bun run dev <map>
bun run export-glb <map>
bun run verify <evidence-target>
bun run infra:publish <root>
bun run infra:deploy <application-build>
bun run infra:release <release>
bun run infra:rollback <release>
```

Each parameter is one stable logical identity from an accepted owner registry. No command accepts a routine machine path, executable path, output root, dependency pin, content-build pin, texture limit, execution limit, retry policy, or concurrency policy. The denominator is Not accepted because required owner interfaces and operation manifests are unavailable and no review record exists.

## Inputs

- Repository-root `playsrc.local.json`, encoded as UTF-8 JSON and containing exactly three non-empty absolute native paths: `tf2Dir`, `sourceCacheDir`, and `assetDir`. Environment variables and command arguments cannot replace or override a field.
- One checked `ToolExecutionPolicy` containing positive integer limits for queued operations, concurrent compilation jobs, concurrent verification jobs, concurrent immutable uploads, owned processes, per-process captured bytes, diagnostics, report steps, graceful-shutdown duration, forced-shutdown duration, retries, and total operation duration. No command supplies or overrides these values.
- One checked dependency and toolchain manifest with immutable runtime, package-lock, compiler, and external-tool identities plus their supported host triples. Setup consumes the manifest and does not discover tools on `PATH` as a substitute for a missing declared identity.
- The current root Owner Registry plus accepted machine-readable operation, target, inventory, evidence, application-build, environment-binding, and release manifests from their sole owners.
- Exact owner interfaces: Content for provider plans and logical-path resolution; format parsers; Map preparation and finalization; Material, StudioModel, Entity, Collision, and Visibility semantic producers; game and ruleset compilers; Asset Store object, root, validation, synchronization, channel, and rollback operations; application build/deployment operations; infrastructure-provided adapters; and owner-defined evidence operations.
- Accepted application and environment lifecycle seams: web product state from `Booting` through `Ready` or a terminal state; service process state from `Configuring` through `Ready`, `Draining`, and a terminal state plus `GET /readyz`; and Infrastructure validation, read-only plan, approved-plan apply, binding, verification, drift, and teardown results. The tool observes and sequences these operations but never recreates their state machines.
- One cancellation signal propagated to every invoked owner operation and every owned child process.

## Outputs

- One final `ToolOperationReport` written as a single JSON object to standard output. Progress and child logs use standard error. The report contains command, logical target, operation identity, status (`succeeded`, `rejected`, `failed`, or `cancelled`), started and finished timestamps, duration, ordered steps, owner/interface identities, input and output hashes, artifact or deployment identities, process outcomes, channel precondition/result when applicable, bounded diagnostics, cancellation boundary, and cleanup result.
- Every step contains exactly owner, operation, sequence, status, input identities, output identities, duration, and one nested owner result or error. Step order is execution order, never asynchronous completion order.
- Success exit code `0`; malformed invocation, configuration, or target exit code `2`; unavailable required owner or dependency exit code `3`; operation, verification, publication, deployment, channel, or cleanup failure exit code `4`; and cancellation exit code `5`.
- Failures use exactly `MalformedInvocation`, `ConfigurationMissing`, `ConfigurationMalformed`, `ConfiguredRootUnavailable`, `TargetMalformed`, `TargetMissing`, `OwnerUnavailable`, `OwnerRejected`, `ProcessFailure`, `PreconditionFailed`, `BoundExceeded`, `Cancelled`, `CleanupFailure`, or `IoFailure`. A nested owner error retains its owner-defined kind and fields unchanged.
- Reports identify configured roots by `tf2Dir`, `sourceCacheDir`, or `assetDir` plus a contained relative path. They contain no credential, raw Source byte, absolute machine path, or command line carrying a secret.

## Invariants

- Every command resolves the repository root from the checked executable location, reads the one repository-root local configuration, validates invocation and configuration before other work, and produces the same invariant outputs from every caller working directory.
- Configuration schema validation precedes filesystem mutation. `tf2Dir` must already be an exact readable directory. Setup may create the exact configured `sourceCacheDir` and `assetDir`; every other command requires all three roots to exist as directories. The three resolved roots must be pairwise distinct and non-nested.
- A map target resolves through its accepted game map registry to exactly `maps/<map>.bsp`, then through Content's configured provider plan. The tool never scans a directory, expands a wildcard, queries an installation registry, searches a library, downloads a substitute map, or probes another extension.
- Compilation invokes owner interfaces in declared dependency order: resolve exact source inputs, parse formats, prepare the map assembly plan, invoke semantic producers from that frozen plan, finalize the canonical map/runtime descriptor, validate every derived object, and optionally submit exact source/derived bytes and descriptors to Asset Store. The tool contains no parser, compiler, semantic resolver, game behavior, or serializer owned by another module.
- An artifact is current only when its recorded exact input hashes, dependency hashes, build configuration, compiler-behavior identity, tool commit, and complete Asset Store closure equal the required values. A mismatch is `build-required`; missing output is `build-required`; a corrupt immutable object is an integrity failure and is never repaired or overwritten. There is no timestamp, schema-version, newer-version, or partial-output freshness path.
- Inventory generation consumes one accepted owner declaration, invokes only that owner's public readers and classifiers, writes only the owner-declared generated path, retains every coverage classification, and installs output atomically only after exact count and metadata validation. The tool does not define inventory items or hand-edit generated output.
- Development performs configuration validation, exact target resolution, stale evaluation, required compilation, owner verification, local immutable publication, then starts the declared local asset service and selected application in dependency order. It prints the exact application URL only after every readiness contract passes.
- The tool owns each spawned operating-system process tree, signal forwarding, startup ordering, readiness timeout, output bound, shutdown ordering, and final reap. Applications and services own their internal lifecycle and readiness semantics. Shutdown requests graceful termination in reverse dependency order, waits the checked grace duration, then terminates only surviving owned trees within the checked force duration.
- `verify` executes the exact checked command or fixed procedure declared by the selected owner evidence target. It cannot invent, weaken, update, or reinterpret the target comparison predicate. An evidence failure is an operation failure and leaves retained expected evidence unchanged.
- `publish` starts from one locally validated retained root, freezes an Asset Store synchronization plan, uploads and verifies missing immutable closure members, and returns without changing a channel. `deploy` starts from one prepared immutable application build and one application-owned deployment plan, invokes the infrastructure-bound adapter, proves readiness, and never compiles or publishes assets.
- `release` starts only from a prepared local root, application build, expected channel revision, and immutable release manifest. It validates and publishes assets, deploys and verifies the application, rechecks the expected channel revision, then requests one conditional Asset Store channel change. Failure before that final change leaves the prior channel unchanged; a stale precondition is reported and never retried against a newly observed revision.
- `rollback` consumes one exact prior release identity naming a retained and remotely verified root plus the expected current channel revision. It changes only the channel through Asset Store. It performs no compilation, immutable upload, application build, object mutation, deletion, or fallback selection.
- Compilation and deployment are separate operations. `publish`, `deploy`, `release`, and `rollback` never compile. `compile` and `export-glb` never deploy or change a channel. Browser cache-miss compilation does not invoke a deployment operation.
- Every long operation propagates cancellation, stops scheduling new work, drains or terminates only owned work, preserves every already committed immutable object, and never changes a channel after cancellation is observed before the channel commit. A cancellation observed after a successful atomic channel commit is reported after that committed result and is never mislabeled as a rollback.
- Each invocation owns one work directory created through the host temporary-directory adapter; no command supplies its path and no artifact or report retains that machine path. Success, rejection after creation, failure, cancellation, and forced child termination all close handles and remove that directory. Cleanup never removes a cache entry, immutable object, retained root, channel, source file, repository file, foreign temporary path, or another invocation's work.
- Supported hosts are exactly the triples in the checked dependency/toolchain manifest. Host adapters normalize logical output, process-tree control, atomic installation, path containment, and signals across accepted Windows, macOS, and Linux triples. Shell parsing and platform-specific command recipes never form the current interface.
- Queues reject new work at their declared capacity. In-flight jobs never exceed `ToolExecutionPolicy`; cancellation and one failed prerequisite remove unscheduled dependents. Parallel completion cannot change target order, artifact bytes, report step order, or failure selection.

## Ownership Exclusions

- Content owns logical-path normalization, provider eligibility and order, archive lookup, raw-source cache validity, provenance, and exact checked-location reports. The tool loads configuration and invokes Content.
- Format, world, runtime, presentation, game, and ruleset modules own parsing, compilation, semantics, state transitions, artifact bytes, media types, and evidence predicates. The tool owns only their executable ordering and reports.
- Map owns map identity, assembly plans, canonical map output, and complete dependency descriptions. Asset Store owns object identity, roots, reachability, retention, synchronization, channel mutation, and rollback semantics.
- Applications own build contents, deployment configuration, internal process lifecycle, readiness semantics, routes, and product behavior. Infrastructure owns provisioned environments, credentials bindings, storage, CDN, compute, networking, and deployment adapters.
- Inspector owns interactive diagnostics. The playsrc tool may start Inspector as an owned process through its declared application contract but cannot implement or alter a diagnostic view.
- Source content acquisition, account authentication, production authorization, infrastructure provisioning, and secret creation are outside setup. A command fails when its exact configured input or authorized adapter is unavailable.
