# Documentation

## Objective

Explain public architecture and integration knowledge that has no single module owner.

## Belongs Here

- Cross-module authority and data-flow explanations.
- Contributor-facing decisions spanning several modules.
- Product and operational concepts shared across applications.

## Does Not Belong Here

- Module objectives, interfaces, invariants, examples, fixtures, inventories, or detailed roadmaps.
- Private research or implementation notes.
- Documentation used to compensate for an unclear module interface.

Domain documentation stays with its owning package, game, ruleset, application, tool, or infrastructure module.
