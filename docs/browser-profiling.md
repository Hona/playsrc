# Headed browser profiling

Run `bun run profile:<scenario> --headed`. Node must be on `PATH`: Playwright's client and reusable WebSocket server run on its supported Node transport; Bun owns preparation and scheduling.

- A machine-wide FIFO queue precedes all build and browser work. Only its selected head attempts the exclusive lock. Older, non-queued commands remain mutually exclusive but do not participate in FIFO ordering.
- The entire command retains its 175-second ceiling, reserving five seconds for cleanup. Active gameplay samples remain 5–10 real seconds. If queue/build time leaves less than 30 seconds for the browser workflow, exit **75** means **capacity deferred**, not failed gameplay or a dead holder. Retry when capacity is available; prepared executable artifacts remain reusable.
- Waiting diagnostics identify the holder, PID, liveness, age and queue position. Only demonstrably exited lock owners are reclaimed. Cancellation removes the caller's ticket; no live holder is killed.
- Development owners require the same worktree, source, configured content and verified generated WASM. Browser processes require the same launch options, transport and executable; every test still gets fresh contexts and storage. Idle owners retain a 60-second lease. Browser retirement also takes the machine lock and records its duration.
- `--fresh` replaces the development owner; it does not bypass build verification or reuse an earlier measurement. Parallel/interactive sampling overrides are rejected.
- Reports live below configured `sourceCacheDir/evidence/tf2-browser-performance/runs/<unique-run>/`. `command.json` records queue observations, successful/failed preparation attempts, owner/build timings, browser fixtures and cleanup. Scenario attachments separate map, sample-and-readback, trace collection/analysis and export. The scenario's browser-clock `elapsedMilliseconds`, not the host RPC/readback interval, owns the active sample boundary. Interrupted commands remain evidence, not cache hits.
